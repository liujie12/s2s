SPEC 01

字段口径：七个键

301 模板由 4 项扩为 7 项

字段与控件

键控件必填值口径
car_brand下拉 + 手填否常用品牌 43 条；不在表内直接手填，≤12 字
car_model下拉单选否车身形式 7 选 1，沿用原键、类型改 select
car_color下拉 + 手填否常用色 5 条 + 手填，≤8 字
plate_no省份下拉 + 字母下拉 + 手填否拼接成单值（如 皖A12345），5–6 位后段

与原有 route / depart_time / seats 并列，车辆四行全部选填（2026-10-31 裁定：必填先全放开，后期按需求再定）；blocker 仍「非空即已填」，四项留空只影响完整度标签，不拦提交。

为什么这么定

  • 下拉为主：常用值点两下就完，减少手打与错别字。
  • 手填兜底：品牌与颜色长尾太大，做封闭选项必然漏；手填保证任何车都能发出去。
  • 车型只做下拉：车身形式本身是可穷举的 7 类，没有手填需求。
  • 车牌拆三段：省份只有 31 个、字母只有 24 个，前两位下拉能挡住绝大多数写错；后段仍手填。
  • 不新增控件类型：仍用现有 text / select，前端决定渲染成下拉还是下拉+手填。
SPEC 02

「下拉 + 手填」的统一交互

品牌 / 颜色共用一套规则

展开与选择

  • 值行：整行可点（≥44），未选显灰字「选择或手填」，已选显实值。
  • 面板：就地展开首屏 6 条常用（可下滑看全部）+ 底部固定「没找到？手动输入」，浮层覆盖下方字段、不撑长卡片。
  • 选中即收起：点一行落值并折叠；再点已选项 = 清空。
  • 手填入口：点底部一行 → 面板收起、该行变输入框并唤起键盘，同时出现「返回列表」小字入口。
  • 手填值：原样保存（如「极石」「香槟金」），不写回选项表、不参与排序。

数据来源与边界

  • 品牌表：前端本地常量（43 条：主流 / 豪华 / 自主 / 商用车），改动发版生效，不做服务端下发。
  • 颜色表：5 条常用色（白/黑/银/灰/蓝），带色点便于扫读；其余色手填。
  • 车型表：7 条车身形式，直接进模板 options（服务端也是这份）。
  • 不做：品牌联想、拼音搜索、最近使用、品牌→车系联动（本期都不做）。
  • 一致性：手填与下拉选出的值在存储上完全等价，都只写 template_values。
SPEC 03

车牌号控件

前两位下拉，后段手填

三段结构

  • 省份：31 个省级简称，7 列网格下拉，默认空、不猜。
  • 字母：发牌机关代号 A–Z，排除 I / O（避免与 1 / 0 混淆），单列或网格下拉。
  • 号码：5–6 位字母数字（新能源 6 位），等宽字体、自动转大写、去空格与「·」。
  • 存值：三段拼成一个字符串写 plate_no（皖A12345），不拆三键。
  • 不校验真伪：只校验长度与字符集，不查号段、不校验字母归属省份。

隐私与展示

  • 选填：车牌属个人信息，不强制填写；留空不扣完整度。
  • 不采集：车牌不进埋点、不进日志（与手机号同一条红线），仅随帖子落库。
  • 详情页：与车型同列为一行「车牌 皖A12345」，不做打码（用户自己填的就是给同路人看的）。
  • 可清空：三段任一段为空即视为整体未填，不存半截值。
  • 键盘：号码段用字母数字键盘，字号与「出发时间」值行一致。
SPEC 04

全局 select 改下拉 + 落地边界

影响 4 个类目的发布表单

这次要动什么

  • 发布页渲染：现有 select 的 ChoiceChip 换成本稿的「值行 + 下拉面板」，全部类目统一（301 拼车 / 101 招聘 / 401 闲置 / 501 家政）。
  • 301 模板：fields 7 项（route / depart_time / seats / car_brand / car_model / car_color / plate_no），必填 3 项（前三个），车辆四行均为选填。
  • 迁移：新增 car_brand（select，43 个 options）、car_color（select，5 个 options）、plate_no（text）；car_model 由 text 改 select + 7 个 options；四行 required 全部为 false；bump template_version。
  • 不改：不新增接口、不改请求体、不动数据库、不新增错误码。
  • 回归：4 个类目的发布表单与相关 widget 测试都要跟着走一遍。

本期不做

  • 车牌校验/查询：不接车管所数据、不做真实性校验。
  • 品牌聚合筛选：手填值会发散，聚合需先规范化。
  • 历史回填：老帖只有 car_model 自由文本，原样展示、不清洗、不补空行。
  • 多车管理：「常用车辆」一类的一键复用不在本期。

R-1

车辆四行的必填要不要保留？

原稿把品牌、车型定为必填；2026-10-31 裁定「必填项要求都去掉，后期根据需求再定」。

A
四行全选填（已定）：只校路线 / 出发时间 / 空座数，车辆信息留空不拦提交、只影响完整度标签。
B
保留品牌或车型必填：信息更整齐，但会挡掉一部分「先发出去再说」的发布。
已按 A 落地（V29）：后期若填写率过低、数据太散，再单独把品牌提回必填。
R-2

品牌下拉先放多少条？

全量 43 条塞进下拉需要滚动；首屏只放 6 条命中率高但热门品牌可能要多点一次手填。

A
面板内 6 条常用 + 可滚动看全部（推荐）：首屏不挤，需要的人往下滑。
B
只放 6 条热门，其余全靠手填：面板最轻，但小众品牌每次都要打字。
建议 A：下拉里能滚到 43 条，手填只是最后的兜底，不是主路径。
R-3

车牌号码段要不要做「·」分隔展示？

车牌习惯写法是 皖A·12345，但存储应为纯字母数字。

A
展示带点、存储不带（推荐）：值行显示 皖A·12345，写入 皖A12345。
B
前后都不带点：最省事，但和用户习惯写法略有差异。
建议 A：只是展示层格式化，不增加存储复杂度。
落地注意：① 301 模板改 fields 必须 bump template_version，否则客户端模板缓存看不到新字段； ② car_model 类型由 text 改 select，历史值不清洗、不迁移，详情照原样展示； ③ 品牌/颜色手填值不写回选项表，也不做「最近使用」，避免脏值回流； ④ 车牌属个人信息：选填、不进埋点与日志、不做真伪校验； ⑤ 全局 select 改下拉会影响 4 个类目，需连带回归发布表单测试，不新增错误码。
