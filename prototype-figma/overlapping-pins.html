同一处多条信息：叠点堆显示数量，点开是一张可选的清单

同一个用户在同一个位置发多条资源/需求是常态，而现在这些点会精确重合： buildMarkers 把未达阈值的簇拆回单点、各回原坐标，hitTestMarker 倒序命中， 于是屏幕上只剩最上面那一枚可点，下面的永远点不到；而分桶键里带了一级大类， 同点不同类更是连聚合圈都不会出现。 本稿在“位置几乎重合”这个尺度上新加一种 Marker —— 叠点堆：主 Pin + 同组其它条的分类色叠影 + 右上角数量角标； 点它不从放大开始，而是直接从底部弹出「这一处有 N 条」的清单，每行是一条完整信息（分类图标、标题、供需·类目·距离·价格、完整度角标）， 点行直接进详情（2026-10-30 用户裁定：清单信息已足够判断，不必再回地图点一次信息卡）；从详情返回时地图停在该条并显示信息卡。

390 × 844 主色 #0B7C8C 间距 / 圆角取 design_tokens 叠点堆 + 展开清单 对照 PRD §6.4.2 / §6.7 / §6.9 本稿只做设计，未改代码

规格说明

SPEC 01 · 什么算“叠点堆”

现有聚合是网格尺度（clusterByGrid 按 NfrPerf.clusterGridSizePx=60px 格 + 一级大类分桶），它解决的是“这一片很密”，不解决“这几条完全重合”。叠点堆补的就是后者：

  • 判定：同一视口下，两点屏幕距离 ≤ overlapStackPx（建议 18，约 Pin 直径一半）即落入同一叠点组。
  • 顺序：先按位置做叠点分组，组内不再按类目拆（这正是修掉“同点不同类永不聚合”的关键）；分组后剩余的点再走原有网格聚合。
  • 优先级：叠点堆是比聚合圈更小尺度的 Marker，同时存在时叠点堆优先，聚合圈只统计“除去已进叠点组”的点。
  • 数量：2 ≤ 组内条数 → 画叠点堆；= 1 → 仍是原来的单点 Pin（样式零变化）。
  • 与阈值解耦：clusterThreshold（work 3 等）只管聚合圈，不再决定“2 条同点”怎么画 —— 2 条同点从“两个重叠 Pin”直接变“叠点堆 2”。

SPEC 02 · 图面：主层 + 叠影 + 数量角标

  • 主层：置顶那条的完整 Pin（实心=资源 / 空心=需求 / 圆心=二级分类字形），尺寸仍 40。
  • 叠影：主层后方向右下偏移 5px、10px 各画一圈白底 + 该条分类色描边，透明度 0.5 / 0.26，最多 2 层（>3 条不再加层，只加数字）。叠影颜色取自组内其它条，让“这里不止一类”可读。
  • 数量角标：右上 #1F2937 底 + 白字 11/700，最小 19×19（两位数字自动加宽），1.5px 白描边。
  • 与 ? 角标的关系：有数量角标时不再画 ?（同位置只能挂一个角标）；需求态仍由 Pin 本体空心表达，逐条供需在清单行内标明。
  • 数字口径：1–9 显示原数，≥10 显示 9+；上限与聚合圈一致，不做 999+。
  • 选中态：整组放大到 48 并加青色光环（复用现有 kSelectedMarkerDiameter 的视觉增量）。

SPEC 03 · 清单：点开就能选

  • 面板：底部 sheet，圆角 24，最大高 72% 屏（与筛选面板同一约束），内容不足时自适应高度。
  • 标题：「这一处有 N 条」+ 位置行（地名 + 各类目条数）；右侧只有关闭（×）。不放「放大地图」：清单本身已经是空间聚集的结果，再放大是第二套语义。
  • 行内容：分类图标（供需同 Pin 的实心/空心规则）→ 标题 → 「供需 · 二级类目 · 距离 · 价格」→ 完整度角标（完整 / 待补 / 空缺，取 🟢🟡🔴 语义）→ ›。
  • 排序：完整度 🟢>🟡>🔴，同级取发布时间新；首行即地图主层那条，带「置顶」小标，让图面与列表对得上。
  • 点行：收起清单 → 直接进详情页（2026-10-30 用户裁定）。清单已含标题/供需/类目/距离/价格/完整度，足够判断；选中态一并写入，从详情返回时地图停在该条并显示信息卡。
  • 关闭：点面板之外的地图任意位置即收起（与筛选面板同一套遮挡处理，遮罩只吃这一下点击，不移动相机）；顶部 × 是同一个动作的显式入口。
  • 无底部按钮：不放「全部进列表查看」「按类目筛」—— 清单就是全部内容，超出即内部滚动。
  • 滚动：超过 6 行内部滚动，底部渐隐提示还有更多。

SPEC 04 · 数据从哪来（现成的坑）

/map/pins 是紧凑格式，只有 id / 坐标 / 类目 / 供需 / 完整度，没有标题与价格；现有信息卡是点开时单独 GET /posts/{id} 补的。清单一次展示 N 条，需要同样的补法：

  • 打开清单时对首屏可见行并发取详情（postDetailProvider(listingId) 已有缓存），滚动到哪拉到哪；未就绪的行标题位先占位、不接受点击。
  • 41001（已下架）行内降级为「该信息已下架」，不可点，与详情页文案同口径。
  • 不往 /map/pins 加标题/价格字段 —— 那会破坏它压体积的前提。
  • 服务端 mode=cluster 时成员 ID 不下发，叠点堆不适用，仍按“点聚合圈放大 2 倍”走；叠加只发生在 pin 模式。

SPEC 05 · 与三种 Marker 的分工

点间距画什么点击语义
≤ 18px叠点堆（主层 + 叠影 + 数量）展开清单，选一条 → 信息卡
18–60px 同格聚合圈（数字，现有）放大 2 倍
其余单点 Pin（现有）选中 + 信息卡

三档互斥，由同一趟分组建 Marker 决定，避免叠点堆与聚合圈吃到同一批点造成重复计数（左下角「附近 N 条」按原始条数计，不受分组影响）。

SPEC 06 · 常量与门禁

  • 新增数字一律进 lib/nfr_constants.dart：overlapStackPx、overlapStackGhostMax、overlapListMaxVisibleRows、overlapBadgeMaxDigits，业务代码不写字面量。
  • 聚合函数仍是纯 Dart（不 import Flutter），叠点分组加在 clusterByGrid 之前，保持可跑 POC 基准。
  • hitTestMarker 的倒序规则不变：叠点堆是一个 Marker，命中它即命中整组，不再有“被压在下面”的概念。
  • 门禁补三条：两条同点同类 → 1 个叠点堆 count=2；两条同点不同类 → 1 个叠点堆（旧实现是 2 个 Pin）；点聚合圈仍是放大而非展开。
REVIEW

待拍板

三项会改变实现路径，需要你定

R-1

点清单里的一行，去哪？

A 与点单个 Pin 一致（收起清单 → 选中 → 信息卡 → 再点进详情）；B 直接进详情页，少一次点击。
A
先信息卡：地图上下文不丢，且全应用只有一套“选一条信息”的手感。
B
直达详情（2026-10-30 用户裁定，已实现）：清单里标题/供需/类目/距离/价格/完整度都齐了，足够判断是不是这条；再回地图点一次信息卡是多余一步。选中态仍写入，从详情返回时地图停在该条并显示信息卡。
R-2

数量角标要不要顶掉 ? 角标？

同一枚 Pin 右上角只能挂一个角标。
A
叠点堆不画 ?（本稿采用）：需求态靠空心本体已可读，数量是更紧急的信息。
B
两个都画（? 左上、数量右上）：信息全，但 40px 的 Pin 上会显得碎。
R-3

叠点阈值取多少？

越大合并越狠、越不容易漏点，但也可能把“确实相邻的两条不同信息”误并成一条。
A
18px（≈ Pin 半径）：只并“几乎完全重合”的，保守、不误伤。
B
28–32px：更激进，密集区更清爽，但会出现“明明分得开却被合起来”的观感。
建议 A，真机看过再决定是否上调 —— 18 已经能覆盖“同一个人在同一地址发多条”这个主场景。
