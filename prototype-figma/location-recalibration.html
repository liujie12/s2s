S2S · DISCOVERY / LOCATION CALIBRATION · PROTOTYPE V1

位置校准与「以这里为中心搜索」：筛选面板左上角位置、搜索地点与地图选点

现状是一个浮动「回到我的位置」按钮，它只把相机拉回本次会话精度最优的历史点，既不改圆心，也不重新取点；拖动地图不产生任何状态，列表仍按旧圆心取数。 本稿把「我现在在哪」与「我按哪里搜」拆成两件事：位置信息放在底部筛选面板的左上角（面板标题位），显示「我的位置 · 文三路 ›」/「地图选点 · 望江路商圈 ›」/「未校准 · 杭州 ›」； 点它，面板就地切成位置视图：搜索地点与地图选点两条路并列，下面是当前搜索位置、当前定位（带重新定位）与最近使用。 地图页本身不多占一行，条件栏只放筛选 chip；确认后位置换来源，半径圈重算，列表同源。

SPEC 01

结构变化

与当前实现对照

位置放筛选面板左上角（美团式面板标题位）

  • 位置：sheet-head 的左侧，替代原来的「筛选条件」标题；右侧保留「重置」。面板高仍 500，不额外加行。
  • 内容：来源 + 地名，如「我的位置 · 文三路」「地图选点 · 望江路商圈」「未校准 · 杭州」，超长省略。
  • 状态：正常用主色图钉 + 深色文字；未校准换 color/warning-text（#B45309）+ 警示图钉，底色由 color/warning 12% 透明度派生，不引入新色值。
  • 点击：面板就地切换为位置视图（同一底部面板，不叠第二层），可用「搜索地点」或「地图选点」两条路改。
  • 地图页不多占一行：搜索栏/条件栏保持原位（52 / 108），位置只在需要改的时候出现。

位置面板：搜索 + 地图选点两条路

  • 第一行：搜索框（占位「搜索小区、商圈、地标」）+ 右侧主色按钮「地图选点」——两种改法在同一行并列，和美团位置页一致。
  • 搜索路：输入即搜，结果为 POI / 小区候选（复用 POST /search/resolve 已返回的 anchor_* 与 community_candidates），按距离排序，点一行即选中并关闭面板。
  • 地图路：点「地图选点」进全屏准星页，拖到位后确认。
  • 当前搜索位置（只读卡片）：地名 + 来源标签 + 「半径 5km 以该点为准，列表与地图共用」。
  • 当前定位行：值 + 「重新定位」，只刷新这一行；最近使用：最多 5 条，可清空。
  • 与筛选面板的关系：两者分开。筛选项属于「看什么」，位置属于「在哪看」；位置再放回筛选面板会让面板涨到 600 且语义混杂（上一版已推翻）。

重新定位：一次取点，只改一行

  • 取点：复用发布侧 HighAccuracyLocator（5s 超时、20m 门槛），不新增接口。
  • 进行态：「当前定位」值变「定位中…」，按钮变「重新定位中」并禁用，防连点。
  • 成功：只更新该行值；若圆心来源仍是「我的位置」，圆心随新点移动；若已是「地图选点」，圆心不动。
  • 失败：保持原值 + 行下提示「这次没取到，可去系统设置检查定位权限」，不弹错误码。

选点页：复用发布侧准星

  • 复用：map_selector_screen 的拖图准星 + 逆地理回显（同一份交互，不新做一个）。
  • 入口：位置面板第一行的「地图选点」按钮（与搜索框并列）。
  • 差异：底部把「门牌号输入」换成「半径档 1/3/5/10/全城」+ 主按钮「以此为中心搜索」。
  • 确认：写 searchIntent.anchorLat/Lng + anchorSource = manual，地图与列表同源。
  • 撤销：回到地图后 3 秒内的 toast 可「撤销」，回落到「我的位置」。
SPEC 02

交互规则

10 条，可直接作为验收项

#触发行为
1打开底部筛选面板面板左上角是位置（来源 + 地名），右侧「重置」；定位失败时为「未校准 · 杭州」。
2点面板左上角位置同一面板就地切到位置视图：搜索框 + 「地图选点」+ 当前搜索位置 + 当前定位 + 最近使用。
2b输入关键词调 POST /search/resolve（已集成的 POI 解析），取 anchor_*/community_candidates 作候选，按距离排序；点一行即选中（写锚点、关面板、半径沿当前档位）。
3点「重新定位」行内进入进行态并禁用；成功只刷新「当前定位」行，圆心仅在来源为「我的位置」时跟随。
4重新定位失败保持原值，行下提示原因；「地图选点」仍可用，不阻断搜索。
5面板内点「地图选点」进全屏选点页，准星初始落在当前圆心；地址随拖动实时更新（沿用逆地理去抖）。
6选点页确认写锚点 + 半径，回地图：左上角位置条切「地图选点 · 地名」，半径圈重算，命中数刷新，列表同源。
7确认后 3 秒内点「撤销」清空锚点，圆心回落到真实定位；3 秒后 toast 消失，锚点保留到本次搜索结束。
8拖动地图不产生圆心状态（维持现状）；松手后右侧出现「查这里」次级入口，点了才写锚点。
9定位失败 ≥ 3 次位置条转警示态「未校准 · 杭州」；不再额外挂提示条，也不弹全屏，不阻断列表。
10列表页复用同一位置条与半径档（AppBar 下、搜索栏上）；空态并列「放宽到 5km」与「换个位置找」两个出口。

SPEC 04

状态矩阵

设计稿未画全的边界态

状态位置条说明
已授权 · 定位成功「我的位置 · 某路」圆心 = 首点；蓝点与圆心重合，半径圈以圆心画。
已授权 · 精度粗（> 门限）「我的位置 · 某路」+ 精度脚注半径圈换为主色虚线圈，圈下标注「约 80m」；1km 档时额外提示误差。

未授权（A/B 态）警示态「未校准 · 杭州」不进全屏引导页，直接在条件栏告知并给出口（与现有 A/B 引导页二选一，见评审 Q4）。
手动选过城市「手选城市 · 合肥」锁定优先级高于自动定位；只有点「用我的位置」才释放。
已地图选点「地图选点 · 某商圈」设备定位继续更新「当前定位」行，但不改圆心。
重新定位进行中不变面板行内进度；面板关闭则静默继续，成功后位置条按来源决定是否变化。
重新定位失败不变行下灰字提示；不弹窗、不改圆心。
锚点已过期（新搜索）回落「我的位置」锚点生命周期到本次搜索结束；跨会话不保留。
无结果不变空态并列两个出口，末尾回显当前圆心，避免用户忘了自己选过哪。
REVIEW 01

评审要点

6 个需要拍板的问题，其余按稿执行

Q0

位置放筛选面板左上角，还是地图页顶部？

本轮按「底部筛选面板左上角」出稿。

A筛选面板左上角（本稿）：改位置与改条件在同一处，地图页不多占一行；看不到位置时说明也不需要改。
B地图页顶部常驻位置条：位置随时可见，但顶部多一层、地图可用区少约 38px。
C两处都放：可发现性最好，但同一状态两个入口，容易一处改了另一处没刷新。
建议 A。代价是「当前在哪」不再一眼可见，需打开面板；换来地图页更干净，且位置与筛选共用一次开合。
Q1

面板里怎么放位置？

位置既要好找，又不能把面板撑高。

A面板标题位（本稿）：不新增行，位置就是面板的标题；点它切到位置视图。
B面板顶部单独一块（浅底卡片）：更醒目，但面板要涨 60–80，条件被挤到下方。
C点进去再开一个二级页：位置更专注，但改一次位置要两次开合。
建议 A。位置与筛选共用一次开合；代价是「当前在哪」只能进面板才看见，需要在别处（如空态末尾）补一句回显。
Q2

选点页的半径怎么来？

进入选点页时，半径档继承当前条件，还是固定回 5km？

A继承当前档，选点页可改，确认时一并写回。
B固定 5km 起步，避免用户在两个地方改同一个值。
建议 A。用户为「找这一带」而来，范围是意图的一部分；B 会让刚设好的 1km 在选点后被悄悄重置。
Q3

锚点活多久？

「地图选点」产生的圆心，是本次搜索、本次会话，还是记到下次打开？

A本次搜索有效，清空条件即回落「我的位置」。
B本次会话有效，切列表 / 切 Tab 仍保留。
C持久化到下次打开（类似美团地址簿）。
建议 A + 会话内软保留。切列表必须保留（否则地图 7 个、列表 12 条）；冷启动回到真实定位，避免用户下次打开以为自己在别的城市。C 属新产品面，不建议本轮做。
Q4

未授权时还进全屏引导页吗？

现有 A/B 态是全屏引导页（替代地图）。本稿改成条件栏警示 + 提示条。

A保留现有全屏引导页，只在 C 态用警示位置条。
BA/B 也降为提示条，先给看得到的结果，再要权限。
建议本轮不做 B（改动面大、涉及 PRD §6.4.4 三态口径）。稿里画的是目标态，落地时 A/B 仍走现有引导页，只把 C 态横幅换成位置条。
Q5

兜底中心写「杭州」还是商圈？

PRD 要求「基站+商圈兜底，不用城市中心假值」，但代码当前就是城市中心。

A先具名披露「未校准 · 杭州」，承认这是兜底；商圈兜底另立条目。
B本轮补商圈兜底（需定位/POI 能力，超出前端范围）。
建议 A。具名披露本身就能消除「为什么结果离我这么远」的困惑；商圈兜底是后端与定位能力问题，不在本轮。
评审提示

还需要产品确认的四件事

①②④ 属口径，③ 属体验取舍：

①锚点算不算「搜索意图」——写进 searchIntent 还是单独状态？影响空态回显与撤销。
②精度门限除了现有 20m，还要不要加「可信 / 较粗」两档阈值（须进常量表，不得写死）。
③拖动地图松手后的「查这里」是次要入口还是不做——不做则只剩「地图选点」一条路。
④地点搜索的调用策略：复用 /search/resolve（已回 POI 锚点与小区候选），但「输入即搜」是防抖 300ms 连续调，还是回车才调一次——后者更省配额，前者更像地图 App。
SPEC 05

落地映射

评审通过后再改代码

前端文件

  • features/discovery/filter_panel.dart：sheet-head 左侧标题换成位置（来源 + 地名 + ›），点击切到位置视图；面板高与四行条件不变。
  • features/discovery/location_panel.dart（新）：位置视图 —— 搜索框 + 地图选点 + 当前搜索位置 + 当前定位（重新定位）+ 最近使用。
  • 地点搜索复用已集成能力：POST /search/resolve 的返回体（SearchResolveResult）本就带 anchor_name / anchor_lat / anchor_lng / anchor_source（source 含 poi）与 community_candidates，见 search_intent.dart:137-156。位置视图的搜索直接复用它，不新增接口、不引新 SDK。
  • 待确认：resolve 是「语音 ASR + 词表 + AI 兜底」的整句解析链路（10s 读超时），纯地名输入能否稳定回 POI 锚点需要实测；输入即搜要么做 300ms 防抖，要么改成「回车/点搜索才调一次」。
  • features/location/high_accuracy_locator.dart：发现侧复用；不新增取点实现。
  • features/publish/map_selector_screen.dart：抽成可复用选点页，底部面板按用途切换（发布：门牌号 / 发现：半径档）。
  • features/discovery/search_intent.dart：写 anchorLat/Lng + anchorSource = manual；列表页已优先读锚点，无需改取数逻辑。

不新增的东西

  • 不新增错误码：定位失败沿用现有降级与文案，`50303` 仍只表示服务不可用。
  • 新增接口仅限一件事：地点搜索（/places/search 代理或 SDK）；/map/pins 与 /posts/search 不动，圆心仍走现有 lat/lng/radius/gridId。
  • 不新增状态对象：锚点复用 searchIntent，不做 SearchCenter 值对象。
  • 不写死数字：超时与精度门限引用 NfrLocation，新增分级阈值须先入常量表。
