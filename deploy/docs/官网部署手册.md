## 2. 架构与路由契约

```
公网 443 ──> nginx(宿主，80/其他子域)  ← 80 冲突，Caddy 不使用 80
        └──> s2s-caddy (容器, 443)  ──静态──> /srv/www (挂载 ../website, 只读)
                                    └──其余──> reverse_proxy app:8080 (Spring Boot)
```

**Caddy 白名单（命中即走文件系统，未命中一律回落 API）**

| 路径 | 行为 |
| --- | --- |
| `/` | `file_server` → `index.html` |
| `/flow` | `rewrite * /flow.html` |
| `/terms` | `rewrite * /terms.html` |
| `/privacy` | `rewrite * /privacy.html` |
| `/download/*` | `file_server`；`.apk` 强制 `Content-Type: application/vnd.android.package-archive`；`Cache-Control: public, max-age=86400` |
| `/assets/*` | `file_server`；`Cache-Control: public, max-age=604800` |
| `/robots.txt`、`/favicon.ico` | `file_server` |
| 其余（含 `/api/*`、`/actuator/*`） | `reverse_proxy app:8080` |

**设计约束（改动前必读）**

1. **不使用 SPA fallback**：未命中路径交给 API，保证既有 404 语义不被静态站吞掉。
2. **只支持无扩展名入口**：`/flow`、`/terms`、`/privacy` 由 `rewrite` 命中；直接访问 `/flow.html` 也会被 `handle /` 之外的 `reverse_proxy` 接住 → 实际表现为 404 JSON。对外一律用无扩展名 URL。
3. **Caddyfile 块必须换行**：`file_server { root /srv/www }` 这种单行块会被适配器拒绝（详见 §9.1）。
4. **80 端口不归 Caddy**：宿主 80 被系统 nginx 占用（服务多个 `build110.com` 子域），Caddy 以 `http_port 8081` 运行并只用 **TLS-ALPN-01（443）** 签发证书；**HTTP→HTTPS 301 须在宿主 nginx 侧配置**。

| 项 | 要求 | 校验命令 |

## 4. 首次部署（实测流程）

### 4.1 拉代码

```bash
cd /mnt/s2s
git log --oneline -1                       # 记录回滚点
git status --porcelain -uno                # 应为空
for i in 1 2 3; do git pull && break || sleep 15; done
ls -l website/index.html website/assets/site.css
```

### 4.2 上传二进制（二选一）

**A. 本地有 SSH 权限（在开发机仓库根目录执行）**

```powershell
scp website/download/zhaoyazhao-V1.0.0.apk root@<服务器IP>:/mnt/s2s/website/download/
scp website/download/zhaoyazhao-flow.png   root@<服务器IP>:/mnt/s2s/website/download/
```

**B. 无 SSH 权限**：阿里云控制台 → 远程连接 → Workbench 文件上传；或先传 OSS，再在服务器用签名 URL `wget -O <文件名>` 落到 `website/download/`。

### 4.3 校验二进制

```bash
cd /mnt/s2s/website/download
ls -l
sha256sum zhaoyazhao-V1.0.0.apk
# 期望 01dbec9224a1e5cbeeeaf4fee1e13bb9e2f97be4ab0bfefedf93da01a553889e
file zhaoyazhao-V1.0.0.apk                # 期望 Android package
chmod 644 zhaoyazhao-V1.0.0.apk zhaoyazhao-flow.png
```

> 首页展示的 SHA-256 必须与实测值**逐字一致**；不一致就不要继续，否则等于向审核方公示了错误的校验值。

### 4.4 确认运行时变量

```bash
grep -E '^(SITE_DOMAIN|ACME_EMAIL)=' deploy/env/.env.prod
# 备案下号前：SITE_DOMAIN=s2s.build110.com
# 备案下号后：SITE_DOMAIN=zhaoyazhaoapp.com（见 §7）
```

### 4.5 离线校验 Caddyfile（**不可跳过**）

```bash
cd /mnt/s2s
IMG=$(docker inspect s2s-caddy --format '{{.Config.Image}}')
docker run --rm \
  -v /mnt/s2s/deploy/config/Caddyfile.prod:/etc/caddy/Caddyfile:ro \
  -e SITE_DOMAIN="$(grep ^SITE_DOMAIN deploy/env/.env.prod | cut -d= -f2)" \
  -e ACME_EMAIL="$(grep ^ACME_EMAIL deploy/env/.env.prod | cut -d= -f2)" \
  "$IMG" caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
```

必须出现 `Valid configuration` 才可继续。此步能在不影响线上的前提下暴露语法错误（§9.1 的故障就是漏了这一步）。

### 4.6 重建 caddy（只动 caddy）

```bash
cd /mnt/s2s
docker compose --env-file deploy/env/.env.prod \
  -f deploy/docker-compose.yml -f deploy/compose/docker-compose.prod.yml \
  up -d --no-deps --force-recreate caddy
sleep 8
docker ps --format '{{.Names}}|{{.Status}}' | grep caddy      # 期望 Up，无 restarting
```

> `--no-deps` 保证不动 `app` / `mysql` / `redis`；`--force-recreate` 是必须的（见 §9.2）。

### 4.7 验收（7 项）

```bash
D=$(grep ^SITE_DOMAIN /mnt/s2s/deploy/env/.env.prod | cut -d= -f2)

docker exec s2s-caddy sh -c 'grep -c "srv/www" /etc/caddy/Caddyfile'   # 期望 9
docker exec s2s-caddy ls /srv/www                                      # index.html assets download ...

for p in "" flow terms privacy; do
  curl -s -o /dev/null -w "/$p -> %{http_code} %{content_type}\n" "https://$D/$p"
done
curl -sI "https://$D/download/zhaoyazhao-V1.0.0.apk" | grep -iE 'HTTP/|content-type|content-length'
curl -s -o /dev/null -w 'health -> %{http_code}\n' "https://$D/actuator/health"
curl -s "https://$D/api/v1/nonexistent" | head -c 120; echo
```

| # | 检查 | 期望 |
| --- | --- | --- |
| 1 | caddy 状态 | `Up ...`（`restarting` 即失败） |
| 2 | 容器内配置 | `9` |
| 3 | `/srv/www` | `index.html`、`assets`、`download`、四个 html |
| 4 | `/`、`/flow`、`/terms`、`/privacy` | `200 text/html; charset=utf-8` |
| 5 | APK | `200`、`application/vnd.android.package-archive`、`124887658` |
| 6 | `/actuator/health` | `200` |
| 7 | 未映射 API | JSON（非 HTML），证明反向代理仍生效 |

**首次上线实测结果（2026-10-23）**：7 项全部通过；APK SHA-256 与页面一致；外部访问 `/` 与 `/flow` 内容完整。

### 4.8 备案号占位

上线初期 4 个页面页脚显示「ICP 备案号：备案办理中」。**这是合规写法**（不得写假号、不得套用其他域名的备案号）。备案下号后按 §7.3 回填。

## 5. 日常更新

| 场景 | 操作 | 是否需要重建容器 |
| --- | --- | --- |
| 改文案 / 改样式 / 改法务正文 | 改 `website/**` → `git pull`（服务器） | **否**（目录级 bind mount，实时生效） |
| 换 APK | 上传新文件 + 更新首页版本号/大小/SHA-256 → `chmod 644` | **否** |
| 换流程图 PNG | 上传覆盖 `website/download/zhaoyazhao-flow.png` | **否** |
| 新增页面路由（如 `/faq`） | 改 `Caddyfile.prod` 加 `handle` → §4.5 校验 → §4.6 重建 | **是** |
| 改缓存策略 / MIME / 安全头 | 同上（Caddyfile 变更） | **是** |

**改 Caddyfile 后的固定动作**：§4.5 校验 → §4.6 重建 → §4.7 验收 1–3 项。

## 6. 迁移部署（换服务器 / 重建环境）

### 6.1 迁移清单

- [ ] 新机安装 Docker + Compose v2，确认 443 可用
- [ ] clone 仓库到 `/mnt/s2s`（与旧机同路径，脚本内多处硬编码该路径）
- [ ] 复制 `deploy/env/.env.prod`（**不入库**，需单独安全传输）
- [ ] 上传 `website/download/` 两个二进制并校验 SHA-256
- [ ] 若新机 80 端口空闲，可选择绑定 80 并改用 HTTP-01（需同步改 `Caddyfile.prod` 的 `http_port` 与 compose 端口映射）；否则保持与旧机一致的「443 + TLS-ALPN-01」
- [ ] 若新机宿主 nginx 同样占用 80，照搬 §2 的端口策略，并在 nginx 侧保留 301 跳转块
- [ ] 数据面（MySQL/Redis/OSS 凭据）迁移不在本手册范围，见《部署操作手册》§7

### 6.2 切换 DNS（低风险顺序）

1. 新机按 §4 完成部署，用 `curl --resolve` 绕过 DNS 验证，不影响线上：

```bash
curl -s -o /dev/null -w '%{http_code}\n' \
  --resolve "$D:443:<新机IP>" "https://$D/"
```

2. 验证通过后，把 DNS A 记录指向新机；TTL 建议提前调到 300s。
3. 观察 30 分钟：`curl -I` 200、证书有效期正常、`/actuator/health` 200。
4. 旧机 Caddy 停止服务（先停 caddy，再按需下线整机），避免两台同时争抢 ACME 证书续期。

> **证书注意**：Caddy 的 `caddy_data` 卷保存证书。新机首次启动会重新走 ACME（需 443 可达）；若想把旧证书带过去，需迁移 `s2s_caddy_data` 卷，否则等待重新签发（通常 10–60s）。

### 6.3 迁移后验收

执行 §4.7 全 7 项，并额外确认：

```bash
curl -sI "https://$D/" | grep -iE 'strict-transport-security|x-frame-options|x-content-type-options'
```

三条安全头必须存在（HSTS / DENY / nosniff）。

## 8. 安全与合规要点

| 项 | 要求 |
| --- | --- |
| 脚本 | 官网全站**零 JavaScript**、无外部 CDN、无第三方统计；新增任何脚本须先过隐私政策与备案公示 |
| 日志 | Caddy access log 已删除 `Authorization`、`Cookie`、`Idempotency-Key` 三类头 |

| 传输 | TLS 1.2+，HSTS 一年含子域 |
| 备案 | 页脚备案号必须与域名一一对应，禁止套用其他域名备案号 |
| 下载 | 只提供官方 APK 直链；页面展示的版本/大小/SHA-256 必须与文件真实值一致 |
| 一致性 | 应用名称「找丫找」、包名 `com.s2s.zhaoyazhao.dev`、签名 MD5、版本号在 App / 官网 / 开放平台三处逐字一致 |

## 9. 故障排查

### 9.1 caddy 反复 restarting / 全站 000

```bash
docker logs --tail 40 s2s-caddy | tail -n 10
```

若出现 `Unexpected next token after '{' on same line` → Caddyfile 里有单行块。改为多行块（`file_server {` 换行写 `root /srv/www`），再走 §4.5 → §4.6。**切勿在未校验的情况下重建生产容器**。

### 9.2 宿主机已改配置，容器内仍是旧内容

```bash
grep -c "srv/www" deploy/config/Caddyfile.prod          # 宿主机（新）
docker exec s2s-caddy sh -c 'grep -c "srv/www" /etc/caddy/Caddyfile'   # 容器（旧）
```

两者不一致 = 单文件 bind mount 仍指向旧 inode（`git pull` 换文件会新建 inode）。`docker restart` **无效**，必须 `--force-recreate`。

### 9.3 根路径返回 `404 application/json`

含义：请求落到了 Spring Boot，**没有命中静态白名单**。按序检查：

1. 容器内 `grep -c "srv/www"` 是否为 9（§9.2）
2. 容器内 `ls /srv/www` 是否有 `index.html`（挂载缺失）
3. `docker inspect s2s-caddy --format '{{range .Mounts}}{{.Source}} => {{.Destination}}{{println}}{{end}}'` 是否含 `website => /srv/www`

### 9.4 页面 200 但样式丢失 / 图片裂图

一律是绝对路径问题：站点用 `/assets/*` 绝对引用，**不能**用相对路径在子路径下打开。本地预览请用 `python -m http.server 8099 --directory website`，不要用 `file://` 直接双击。

### 9.5 APK 下载得到 JSON 或 404

1. 文件是否上传（§4.2）、是否被 `git clean` 清掉
2. `ls -l website/download/`；容器内 `ls /srv/www/download`
3. 路径大小写必须与页面链接完全一致

### 9.6 证书签发失败

```bash
docker logs --tail 60 s2s-caddy | grep -iE 'acme|certificate|challenge'
```

常见原因：域名未备案被网关拦截、DNS 未指向本机、443 不可达、同域名有另一台机器在跑 ACME。修复后重建 caddy 触发重试。

### 9.7 `http://` 访问出现 `403 Server: Beaver`

阿里云备案拦截，**不是配置问题**。先完成 ICP 备案；下号后自动解除。

## 11. 已知限制

| 限制 | 说明 | 触发条件 / 后续 |
| --- | --- | --- |
| 不支持 SPA fallback | 未命中路径回落 API，前端路由不能靠 Caddy 兜底 | 未来若做多页扩展，逐条加 `handle` |
| 只认无扩展名入口 | `/flow.html` 直链会落到 API 并 404 | 对外链接统一用 `/flow` |
| 单机单实例 | 无 CDN、无多地域 | 访问量上来后再接 CDN（注意缓存与备案一致性） |
| 二进制不随仓库 | 迁移/重建必须手工上传 | 已在 §6.1 列为清单项 |
| 无 CMS | 文案变更走 Git 提交 | 已裁定，不做后台 |
