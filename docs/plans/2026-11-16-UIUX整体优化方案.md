# 找丫找 · UI/UX 整体优化方案
> 版本：v1.2（2026-11-17，六维视觉追平与真实供给修订；同日完成两轮文档评审并收口目标值与出口判据）
> 定位：对标 58同城 / 闲鱼 / 啄木鸟家庭维修 后的**端到端视觉、内容与体验改造编排**。本文只做「改什么、按什么顺序改、怎么判达标」，取值口径一律引用《设计系统与组件规范》，业务口径引用《PRD》，不复制其条文。
> 适用对象：Flutter 客户端（`lib/`）、Figma 真源（`prototype-figma/code.js`）、既有 IP 与分类字形资产、封面缩略图相关的后端签名链路、真实供给与媒体质量治理。

## 0. 结论先行

**诊断**：问题不是「没有设计规范」，而是**规范落地率低、资产层没有进入信息层、真实内容没有被有效呈现**。只补阴影、字号和动效，无法解决页面「素」。

- 规范侧已有：43 项 Token、34 组对比度实测、6 档动效、20 个组件 master、卡片阴影规格。
- 实现侧缺失：卡片阴影未落、6 档动效 0 落地、列表 0 张图、0 张插画、0 次触觉反馈；鸭子符号已在启动页 / 登录页 / Tab 中键出现，但**从未进入信息层**（卡片、图例、空态）。
- 视觉侧缺口：视觉风格、配色审美、版式节奏、插画 / IP / 图形语言均未形成整屏一致性；既有资产只承担小角标，没有形成足够面积的视觉记忆。
- 内容侧缺口：搜索卡封面尚未由服务端有效填充，真实封面率、有效供给密度、零结果率均无基线；因此「内容少」与「内容没有呈现出来」尚不能区分。
- 结果：页面「干净但不成立」——既缺信息锚点，也缺竞品所具备的图片内容感、图形完成度和真实界面活力。

**本轮已决目标**

视觉风格、配色审美、版式节奏、插画 / IP / 图形语言质量、内容观感（图片与真实供给密度）、界面「热闹程度」全部进入正式交付与验收，**以各维度最佳竞品参考为追平方向**，不再以零商业化或工程合规为由回避。(session-settled: user-directed — chosen over 只做工程合规、不以竞品视觉完成度为目标: 六个视觉与内容维度本身就是解决页面很素的核心)

**转化校验（决定后续加码，不用于否定视觉目标）**

> 「页面素 ⇒ 用户不敢点 / 留不住」目前是**假设而非结论**：本文没有内测反馈、漏斗数据或走查记录支撑它。因此转化与视觉完成度分开验收：
>
> **首轮核心屏改造上线后，列表卡 → 详情点击率、详情 → 首次联系触发率至少一项显著高于改造前基线。**
>
> - 基线：Phase 0 开工前用当前内测包采集两个事件各 7 天（同城、同入口）。
> - 判定口径：Phase 0 与埋点同批预登记检验方法、显著性水平、最小可检测效应与每城最低每日事件数；样本不足按「未验证」处理并顺延结论，不临时约定。
> - 可比性：复测固定入口、曝光卡数与排序口径；若采用双列图片流，另设单列对照组，或把双列上线推迟到转化结论之后。
> - 判据：Phase 3 复测。两项均未显著上升则记录「视觉改善未转化为业务提升」，下一批次不再新增视觉条目，腾出容量回填 Batch2 在册条目并登记责任人；已交付的信息层级、真实内容、无障碍与一致性成果不回退，G4~G6 仍须如实验收。
> - 事件名与埋点口径由数据侧在 Phase 0 立项时补齐，此处不自行定义。

## 2. 设计原则（改造必须同时满足）

1. **可信与视觉完成度并重**：真实图片、供给与状态是内容，风格、配色、版式、图形和反馈负责把内容呈现出来；两组工作都必须交付。
2. **六维同步追平**：每个核心屏同时检查视觉风格、配色审美、版式节奏、插画 / IP / 图形语言、内容观感、界面活力，不允许只用 Token 合规代替视觉验收。
3. **先定稿，后冻结 Token**：同一组真实供给数据制作候选方向，匿名盲评选定唯一方向后，才回写 `code.js`、规范与 Dart Token。
4. **热闹只能来自真实**：真实 Pin、真实封面、有效供给、距离、新鲜度、分组结果与即时反馈可以营造活力；假卡、假热度、假在线、商业促销位一律不算。
5. **资产扩展不换画风**：复用鸭子 IP、分类字形和供需符号的既有骨架，建立可复用动作 / 场景 / 插画库；矢量优先，必要位图按资源预算审核，不再设「包体增量必须为 0」的过度限制。
6. **性能与无障碍是设计约束**：图层切换 P95 ≤ `NfrPerf.layerSwitchP95Ms`；动效只动 `opacity` / `transform`，不动布局与几何；信息密度不得靠缩字号、缩热区硬塞。
7. **Token 单一真源**：任何取值改动走 `code.js` → 导出脚本 → probe 断言，禁止手改生成物、禁止页面内联字面量。

## 3. 总体结构：六条工作线

| 工作线 | 解决什么 | 对应问题 |
| --- | --- | --- |
| **W0 方向与内容前置** | 竞品方向定稿、封面链路、真实内容基线 | 「不知道追平什么」「列表没有真图」「供给多少说不清」 |
| **W1 视觉基座** | 配色、字体、光影、间距、动效能力 | 「颜色平」「层级弱」「卡片不像卡片」「点了没反应」 |
| **W2 卡片与版式节奏** | 首页 / 列表 / 详情 / 发布的版式、内容锚点与密度 | 「列表像公告板」「每屏节奏一样」「没有第一落点」 |
| **W3 地图视觉语言** | 让「实心=有资源 / 空心=有需求」在地图上可读 | 「供需双态用户看不见」（完整度不进 pin，见 §9） |
| **W4 品牌与图形语言** | IP、分类字形、插画、供需符号与分享素材 | 「无创新亮点」「图形不成体系」「记不住」 |
| **W5 真实供给与界面活力** | 封面质量、有效供给密度、零结果承接、状态反馈 | 「内容观感弱」「页面冷清」「空结果更空」 |

依赖关系：`U-19 方向定稿 → U-20 视觉规格 → U-01~U-04 Token / 主题`；`U-00 → U-05 / U-23`；`U-19 + U-20 → U-21 / U-22 / U-24`；核心屏与地图共用 U-15 / U-22 的图形语法。W4 的分享卡依赖 W2 的卡片组件，真实供给不足时只能衔接 PRD 既有 S2，不得以视觉填充代替供给治理。

## 4. 分阶段实施

### Phase 0 · 六维方向定稿 + 真实内容前置（起止日随 Batch2 容量重定）

> 原「11-25 提审前」时间锚已失效。Phase 0 先决定「追平什么样、真实内容有多少」，未完成本阶段不得先改 Dart Token 锁定方向。

- **U-19 竞品视觉方向稿与盲评定稿**：同一组真实供给数据覆盖首页 / 列表 / 详情 / 发布 / 零结果，候选方向只改视觉与呈现，不改业务口径。
- **U-00 后端封面与缩略签名**：未完成则 U-05 / U-23 只能画占位块。
- **U-23 / U-24 基线部分**：冻结真实评审数据集，登记有审封面率、有效供给密度、零结果率及图文比例；转化事件按 §0 采集基线。

**出口判据**：唯一视觉方向经六维匿名盲评**定稿且逐维达到 U-19 预登记的六维门槛**（以最佳参考为基线登记容差），未达标者重做候选、不得进入 Phase 1；当前构建的同标尺六维盲评基线已登记；真实数据集与竞品参考组可追溯且已按 U-19 脱敏条款处理；U-00 的缩略图链路可用；三项内容指标已回填 §1 或附基线表。此阶段只出方向与基线，不宣称已追平。

### Phase 1 · 视觉基座 + 核心屏版式 / IP / 内容活力（Phase 0 出口后启动）

- U-20 → U-01 ~ U-04：先落实定稿的配色、字阶、光影与间距，再走 Token 生成链和主题层。
- U-21、U-05 / U-06 / U-07 / U-09 / U-10：核心屏版式节奏、卡片、层级、完整度、骨架与按压。
- U-22、U-08、U-15：既有 IP / 插画 / 分类字形 / 供需符号进入信息层。
- U-23、U-24：真实封面质量、非阻断补图、有效供给密度与既有 S2 空圈的视觉化。

**出口判据**：核心屏与定稿方向一致；G1 / G3 / G5 达标；G2 部分达标（卡片 elevation 100% 走 Token，`page` / `sheet` / `mask` / `press` 四档与 U-09 的 `fade` 均有实现与测试证据）；核心屏六维盲评有阶段读数（可用较小样本，不足记「未验证」）；有图、无图、长标题、媒体失败、上传中、零结果等状态完整；G6 有同域复测；`flutter analyze`、`flutter test` 全绿。U-19 / U-20 / U-21 / U-22 / U-23 / U-24 不得被降级成「只改 Token」。

**让路规则**：与 Batch2 在册条目冲突时可整条顺延，但不得删除六个视觉维度或拆掉其验收；顺延项及容量影响必须同步登记 Batch2 与《说明文档》§3。

### Phase 2 · 地图视觉语言 + 分享与过程表达（Phase 1 出口后启动）

- U-11 ~ U-13：pin 选中态、图层切换淡出淡入、进场 stagger；重点落地 `layer` 档，并按 §7 汇总复核六档动效的实现证据与默认状态。
- 本阶段只做地图视觉与压测；U-16 / U-17 移到 Phase 3 之后的条件加码，不占本阶段容量。

**出口判据**：

- 地图可读性与性能修复：动效关闭态图层切换 P95 ≤ `NfrPerf.layerSwitchP95Ms`，5 万点场景帧时间不劣化。
- 六档动效的实现与测试证据汇总复核完成（含 U-09 的 `fade` 与 U-12 的 `layer`）；未开闸档不计入默认可见数量，但仍须保留证据。
- U-12 默认开闸另判：动效开启态 P95 ≤ `NfrPerf.layerSwitchP95Ms` 且 5 万点帧时间不劣化，未通过则保持默认关闭。

> Batch1 记录的 353ms 本身已超 300ms 且被裁定「仅登记不改」，作为**独立待偿还项**登记：不得作为「不退化」的比较基线，不阻塞 Phase 2 出口，但阻塞 U-12 默认开闸。Phase 2 开工前先重测一次并登记可用基线。

### Phase 3 · 六维验收 + 度量收口 + 视觉回归（2027-01）

- 建立首页 / 列表 / 详情 / 发布 / 空态及有图 / 无图等关键组合的 golden 基线，并完成真实尺寸、最近邻放大和实机几何复核。
- G1~G6 复测；G4 使用同一竞品参考组与真实数据样本匿名盲评，样本不足时明确记「未验证」。
- 运行设计能力库适用的 `check` / `gate` 并保存结果；未运行的判据不得宣称通过。
- **动效开闸**：图层切换 P95 ≤ `NfrPerf.layerSwitchP95Ms` 且 5 万点场景帧时间不劣化，才把对应动效档默认打开；未开闸档不计入 G2 默认可见数量，但六档仍均须具备实现与测试证据。
- 转化假设复测并回填本文与《说明文档》§3；出口判据成立时才输出本文 v1.3。

**出口判据**：G1~G6 全部按预登记阈值判为达标；G4 必须给出「达标 / 不达标」二分，使用同屏类实机截图与 Q8 预登记样本量，「未验证」视同未达标；**设计能力库七步门禁须在 Flutter 桥接后跑通**（Dart 侧硬编码扫描、Widget variant 登记、golden 视觉回归三项至少可用），仅文档级承接不足以判定通过；任一条件不满足时判 Phase 3 未达成，输出差距清单并把「继续迭代」挂到具体 U 条目与下次复测时点，不产出宣称已追平的 v1.3。未达成不影响已交付的信息层级、真实内容、无障碍与一致性成果。

### Phase 3 后 · 条件加码（不阻塞收口）

## 6. Token 变更流程（不可跳步）

0. **先完成 U-19 唯一方向定稿与 U-20 视觉规格**。探索期可保留多个 Figma 候选方向，但不得同步到 Dart Token。

3. `node prototype-figma/export-dart-tokens.js` → `lib/design_tokens.dart`。
4. `node prototype-figma/export-spec-doc.js` → `docs/设计系统与组件规范.md`。
5. 更新两个 probe：`probe-token-vars.py`（26 色 / 17 尺寸为硬断言；「动效不得导出到 Dart」断言须按 U-03 改写）、`probe-layout-offline.js`。规范登记值同提交更新。
   5.1 若改动字阶 / 间距 / 圆角 / 卡片阴影，同提交更新 PRD §1.4.4 / §1.4.5 / §1.4.7 的设计规格表——属设计规格变更，不是业务口径变更。
6. `flutter analyze` + `flutter test` 全绿后提交；**真源、Dart、规范、PRD 设计规格表、两个 probe 五处一致**后提交。

## 9. 红线与不做清单

**不做（产品红线）**
- 评分、钻石/金银铜等级、五级权限阶梯、任何曝光特权。
- 热力图、五层金字塔、图层筛选面板、行动导航器。
- 运营 Banner / 红包 / 直播 / 关注粉丝体系。

**不做（内容真实性）**
- 不用假卡、重复卡、假封面、假数量、假在线、假热度制造「热闹」；不把历史 / 全城结果混充当前结果。
- 不把图片改为发布必填，不以补图承诺升绿、曝光、评分或信誉；不静默丢弃上传中 / 失败的已选媒体。
- 不公开非 pass 媒体，不另造一套空圈状态机，不用视觉方案修改 PRD 业务口径。

**不做（设计系统约定）**
- 不把完整度搬回 pin（pin 只承载「分类 + 供需态」）。
- 不扩用 `accent` 到价格等普通信息，不用 emoji 充当跨平台正式图形，不另起与既有 IP / 分类字形无关联的画风。
- 不引入中文字体包（体积不可接受）；层级靠定稿字阶 / 字重 / 颜色建立，数字可用等宽数字特性。
- 不为动效牺牲布局稳定性（禁止高度动画引发列表跳动），不靠缩字号 / 热区提高密度。
- 双列图片流未确认入口、默认态、记忆、大字体与字段降级前，不直接替换单列实现基线。

**不做（数据与凭证）**
- 签名 URL（含查询串签名）、`Authorization` 头与联系方式不得写入应用日志、访问日志、崩溃上报或分享卡；排障只记对象键与错误码。
- 冻结真实评审数据集、golden 基线与盲评材料不得含未脱敏的真实昵称、头像与用户照片；golden 用脱敏或合成样本。

## 10. 风险与回退

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 方向未定稿先改 Token | 锁定错误风格，核心屏返工 | U-19 / U-20 是硬前置；候选稿只留在设计侧，定稿后走 §6 生成链 |

| 冷启动封面率低于锁定门槛 | G1 ② 不达标，Phase 1 无法出口 | 用分类字形兜底占位并顺延门槛复测；不造假封面、不调低门槛、不把「面议」当缩略图 |
| 评审数据集含真实用户信息外泄 | 隐私与合规风险 | 入库前统一脱敏；golden 用脱敏或合成样本；Figma 候选稿与对外盲评材料只用脱敏样本，访问范围与留存期登记入 Q8 |

| 封面率低或图片质量差 | 内容观感仍弱 | U-00 / U-23 同时解决下发、裁剪、补图与失败态；按同域基线设阶段门槛，不编造目标值 |
| 动效拖慢图层切换 | 北极星轴 2 退化 | 动效做成开关、默认关；Phase 3 按绝对值判据开闸，未开闸档不计入 G2 默认可见数量，但六档仍均须具备实现与测试证据 |
| 缩略图拉取增加流量与首屏耗时 | 列表观感变慢 | 仅 `cover_url` 非空才请求；限制并发与预取数量；缩略规格由后端签名时带入，禁止前端拼 `x-oss-process` |

| IP / 插画扩展后风格碎裂 | 页面更花但没有品牌感 | 所有新增资产回到 U-22 的既有骨架与动作库；真实尺寸、最近邻放大、实机三轮验收 |

| Token 计数断言变红 | 门禁阻塞 | U-01~U-03 / U-20 与 probe 断言同提交（见 §6） |
| 视觉改造与在途功能冲突 | 返工 | 按 §4 让路规则整条顺延并登记，不删除六维验收；卡片改造以组件为界，不碰数据层与状态层 |
