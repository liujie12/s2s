## 工作方式变更（重要，含一次失败的排查）

**结论：在主仓库 `d:\developer\code\aicoding\s2s` 上、切到分支 `item/123-auth-domain` 工作。worktree 方案已废弃。**

原计划用 `s2s-wt-lane-a` worktree 隔离，**失败并已放弃**。失败根因（实测 8 组对照得出，勿重复排查）：

- 沙箱 `shellSandbox` 的 `resourceAuthorization` 白名单**只对直接命令生效**；`mvn → java/javac` 的**子进程写入不被覆盖**。
- 对照证据：PowerShell 直接写 worktree 的任意路径（含深层目录、含 `$` 文件名）**全部成功**；同一目录下 `mvn` 编译**必然失败**，报 `TRAE Sandbox Error: hit restricted`。
- 主仓库能跑通，因为它是 Trae 的 workspace 根，整棵进程树放行。
- 已试并**无效**的手段（勿再试）：改 `global.json` 加路径（含带 `/**` 递归）、`requires_approval: true`、`mvn -f <worktree>/pom.xml`（cwd 留在主仓库）、删 `target` 重跑。
- 用户在两轮选择后最终选定「主仓库 + 现有分支」。

**残留（需用户手动处理）**：目录 `d:\developer\code\aicoding\s2s-wt-lane-a`（machine-local）仍存在，沙箱不允许工具删除。它**已不是登记的 git worktree**（`git worktree list` 无此项），无功能影响，可直接手工删除。

## 已完成

### U1 加解密基础件（完成，测试全绿）

分支 `item/123-auth-domain`。文件（仓库相对路径）：

- `src/main/java/com/s2s/server/common/crypto/BlindIndex.java` —— HMAC-SHA256 盲索引，返回 **32 字节 `byte[]`** 直映 `BINARY(32)`；取 `version` 数值最大的 pepper。
- `src/main/java/com/s2s/server/common/crypto/CryptoFacade.java` —— 全系统唯一加解密入口；`EncryptResult encrypt(String, String)` 与 `String decrypt(byte[], String, int keyVersion)`；密文布局 `iv(12) || ct`。
- `src/main/java/com/s2s/server/common/crypto/Pepper.java` / `MasterKey.java` —— `record (int version, byte[] key)`，`of(int, String)` 入口。
- `src/main/java/com/s2s/server/common/crypto/KeyEncodings.java` —— hex/base64 宽容解码 + `aadBytes`，两处共用以防漂移。
- `src/main/java/com/s2s/server/common/config/CryptoConfig.java` —— 密钥列表 JSON → `@Bean`，启动期快速失败。
- 测试：`src/test/java/com/s2s/server/common/crypto/{BlindIndexTest,CryptoFacadeTest}.java`（8 + 13 = 21 个用例）。
