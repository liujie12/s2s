# 举报工单临时处理手册（后台 UI 上线前）

> **定位**：运营治理后台的举报工单页面尚未开发期间的**临时操作手册**。
> 用的不是“后门”，而是已随 Batch2 落地的正式后台接口（`/admin/reports*`），
> 带 RBAC、同事务审计与统一错误码；后台 UI 上线后只是换一层界面，接口与数据不变。
>
> **适用范围**：内容审核员、超级管理员。`operator` / `algo` 角色调用一律回 `40305`。
>
> **契约真源**：[openapi.yaml](file:///d:/developer/code/aicoding/s2s/docs/api/openapi.yaml) 的 `/admin/reports*`。

---

## 0. 操作前后必须知道的三件事

1. **所有处理都写 `audit_log`**（≥180 天，变更前后值可读）。脚本不是“隐形操作”，下架与回撤都能追到人。
2. **查看详情/会话正文也写审计**。不要拿脚本高频轮询这两个接口，否则审计表会被“查看记录”灌满。
3. **下架走的是审核下架**（`status_reason=2`），帖子作者可在 App 内申诉；申诉成立会恢复上架并清零该帖累计风险分。

## 1. 前置

| 项 | 值 |
|---|---|
| 后端地址 | 本地默认 `http://localhost:8080`（未配置 `server.port`） |
| 后台账号 | `admin_user` 表中的账号，角色须为 `auditor` 或 `super_admin` |
| Token 有效期 | 120 分钟，过期重新登录 |
| 路径前缀 | 后台接口**不带** `/api/v1`，直接是 `/admin/...` |

> 账号口令从部署环境获取，**不要写进本文件或聊天记录**。

---

## 2. 登录拿 Token（PowerShell）

```powershell
$Base  = "http://localhost:8080"
$Login = Invoke-RestMethod -Method Post -Uri "$Base/admin/login" `
  -ContentType "application/json" `
  -Body (@{ username = "auditor01"; password = $env:S2S_ADMIN_PASSWORD } | ConvertTo-Json)

$Token = $Login.data.token
$Role  = $Login.data.role
$Token
```

后续请求统一带：

```powershell
$H = @{
  Authorization     = "Bearer $Token"
  "X-Interaction-Id" = [guid]::NewGuid().ToString()
}
```

写接口（处理工单）再补幂等键，**每次新操作换一个新的 UUID**：

```powershell
$HW = $H.Clone()
$HW["Idempotency-Key"] = [guid]::NewGuid().ToString()
```

> 失败一律回 `40101`（不区分账号不存在/口令错/禁用/角色非法），这是防账号枚举的既定口径。

## 3. 查工单队列

```powershell
$Page = Invoke-RestMethod -Method Get -Headers $H `
  -Uri "$Base/admin/reports?status=pending&page=1&page_size=20"
$Page.data
```

| 参数 | 说明 |
|---|---|
| `status` | 缺省 `pending`；处理过的工单为 `handled` |
| `reason` | 可空；`misblock` 为会话内“误拦反馈”专用队列 |
| `page` / `page_size` | 默认 20，上限 100 |

排序为**被举报帖子累计风险分降序**，同分按举报时间升序。响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "items": [
      {
        "report_id": 88,
        "post_id": 1001,
        "post_title": "专业家庭日常保洁",
        "reason": "fraud",
        "weight": 50,
        "status": "pending",
        "is_false_report": 0,
        "risk_score": 50,
        "created_at": "2026-11-02T13:20:00Z"
      }
    ],
    "total": 1,
    "page": 1,
    "page_size": 20
  },
  "request_id": "req_7f3a91c2"
}
```

> `risk_score ≥ 60` 时服务端已自动下架并进人工复核，队列里仍能看到该工单（`status` 仍为 `pending`，等人工结论）。

## 4. 看工单详情（含说明与凭证）

```powershell
$Detail = Invoke-RestMethod -Method Get -Headers $H `
  -Uri "$Base/admin/reports/88"
$Detail.data
```

响应示例：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "report_id": 88,
    "post_id": 1001,
    "post_title": "专业家庭日常保洁",
    "reason": "fraud",
    "description": "对方要求先转 200 元定金",
    "evidence_urls": [
      "https://oss.example.com/evidence/xxx.jpg?Expires=..."
    ],
    "weight": 50,
    "status": "pending",
    "is_false_report": 0,
    "risk_score": 50,
    "created_at": "2026-11-02T13:20:00Z",
    "handled_at": null,
    "handler_id": null
  },
  "request_id": "req_..."
}
```

要点：

- `description` 是用户补充说明（契约字段名 `remark`）。
- `evidence_urls` 是**限时签名 URL**，过期后重新拉一次详情即可；已删除/非法的凭证会被过滤，不阻断整单查看。
- 本接口**每次调用都写一条查看审计**（`report.detail.view`）。

## 5. 看双方会话正文（可选）

仅当工单来自会话内举报、需要看上下文时使用：

```powershell
Invoke-RestMethod -Method Get -Headers $H `
  -Uri "$Base/admin/reports/88/conversation" | Select-Object -ExpandProperty data
```

- 返回该会话最近一页消息（按 `seq` 正序）。
- **同样是敏感操作**：读取与审计同事务，逐次记录操作人、角色与会话 ID。
- 帖子已下架不影响本接口（举报材料要保留取证）。

## 6. 处理单条工单

两个互斥动作：

| `action` | 后果 |
|---|---|
| `offline` | 对被举报帖子执行审核下架（`status_reason=2`），工单置 `handled` |
| `false_report` | 打标误报（`is_false_report=1`）并**回撤**该条举报的风险分贡献，工单置 `handled` |

```powershell
$Body = @{ action = "offline" } | ConvertTo-Json

Invoke-RestMethod -Method Post -Headers $HW -ContentType "application/json" `
  -Uri "$Base/admin/reports/88/handle" -Body $Body
```

- 处理成功返回 `{"code":0,"message":"ok","data":null}`。
- **已处理过的工单再处理 → `40001`**（幂等靠状态判定，不靠重复执行）。
- 动作值非法 → `40001`；工单不存在 → `40001`；越权 → `40305`。
- 本操作属“必留操作”，处理与审计同事务；审计里能区分 `false_report` / `offline`。

## 7. 批量处理

```powershell
$Body = @{
  report_ids = @(88, 89, 90)
  action     = "false_report"
} | ConvertTo-Json

Invoke-RestMethod -Method Post -Headers $HW -ContentType "application/json" `
  -Uri "$Base/admin/reports/batch-handle" -Body $Body
```

- 单次上限 **100 条**（超限 `40001`，不静默截断）。
- **整批同事务**：任一条不存在/已处理/动作非法 → 整批回滚，不留“一半下架一半没下”的中间态。
- 审计**逐条写**，每条工单都能单独追溯。

---

## 8. 错误码与排查

| 现象 | 码 | 排查 |
|---|---|---|
| 登录失败 | `40101` | 账号/口令/角色/禁用，不区分原因（防枚举） |
| 缺 Token 或 Token 过期 | `40101` | 重新登录；后台 Token 与 C 端 Token 互不认 |
| 角色不是审核员/超管 | `40305` | 换 `auditor` / `super_admin` 账号 |
| 工单不存在 | `40001` | 检查 `report_id` |
| 工单已处理 | `40001` | 队列按 `status=handled` 复核，不要重复处理 |
| 批量超 100 条 | `40001` | 拆批（每批 ≤100） |
| 动作值非法 | `40001` | 只接受 `false_report` / `offline` |

## 9. 已知边界（当前阶段）

1. **举报人暂时收不到处理结果**：App 通知中心只有系统/互动/认证三类，尚无“举报处理结果”通知。临时阶段由运营按需人工跟进；上线前需决定补通知类型或回改 PRD §9.10.3 的“24h 闭环反馈”。
2. **`evidence_urls` 会过期**：后台 UI 上线后应在前端处理“重新拉详情换新 URL”，不要把 URL 存库。
3. **本手册只覆盖举报工单**：分类配置、认证审核、临时类目等其它后台能力各有自己的接口与页面。
4. **文档口径**：PRD §12 前言已回写为“后台页面 UI 待补齐，举报工单后端接口已随 Batch2 落地”，与本手册一致。
