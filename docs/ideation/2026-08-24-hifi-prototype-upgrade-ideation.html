PRD 单一真源表：先修三处口径冲突，再动一行视觉

状态覆盖矩阵confidence 高complexity 低
做什么
在 code.js 顶部建一张从 PRD 抄录的常量表（半径档、过程态时间轴文案、状态清单），所有生成函数只读这张表；同时补齐两个缺失状态画框。冲突处以 PRD 为准。
basis
direct: 半径档 code.js:2190 为 1km/3km/10km/全城，而 PRD.md:947-952 为 3km/5km/10km/全城；过程态首行 code.js:2150「骨架屏：地图底图先出」，而 PRD.md:975 为「鸭子 IP 缺省图 + 附近有点安静，正在帮你往外找… + 骨架卡 3 条」；PRD.md:985（全屏权限引导页）与 PRD.md:1320（已下架详情态）在 code.js 变体清单中无对应画框。
为何重要
高保真的定义是「与规格一致到能直接给开发」。若在错误的半径档和错误的过程态文案上做视觉精修，M3 冻结的稿子会带着规格偏差流向实现，返工成本远大于现在改三个数组。
风险
  • PRD 本身可能是过期的一方 —— 需先与你确认哪一侧为准，不能默认 PRD 永远对
  • 补两个新状态画框会打乱现有 SECTION_Y 布局排布

CONTENT fixtures 层：把 PRD 文案抽成数据，页面只做渲染

真实内容与数据密度confidence 高complexity 中
做什么
为五大 P0 页（login / publish / home / detail / contact）各建一份 fixtures 数据对象，字段名对齐 PRD 页面清单，值用 PRD 原文文案与拟真业务数据；至少覆盖完整度三档（🟢/🟡/🔴）各一条样例。页面构造函数改为吃 fixtures。
basis
direct: PRD.md:1469-1484（§9.8）给出完整度三档的唯一判定口径；PRD.md:1557-1579（§10.1）列出 17 页（14 页 + 3 模态）的页面清单与字段归属。侦察已逐项比对出现有 code.js 占位文案与 PRD 字段的缺位对照。
为何重要
北极星指标之一是「🟢完整发布率」（PRD.md §0.2）。如果原型里看不出 🟢/🟡/🔴 三档的视觉差异，评审时就无法判断完整度引导设计是否有效 —— 这是本产品最该在原型阶段验证的一件事。
风险
  • fixtures 与 PRD 会各自漂移，需约定 PRD 为唯一编辑入口
  • 真实文案变长后，现有固定高度画框会溢出，需同步改 Auto Layout

batchHifi：高保真独立 Page，自成闭环

视觉与组件精修confidence 高complexity 中
做什么
新增 PAGE_NAMES.hifi = '02 · 高保真主页面' 与第七个批次入口 batchHifi，复用 _components · master（勿删） 的 20 个 master（Component 可跨 Page 实例化），但所有跳转目标全部落在本 Page 内。batchClean 需增加对新 Page 的清理分支。
basis
direct: 跨 Page 跳转硬限制已实证 —— setReactionsAsync 的 NODE 型 action 的 destinationId 必须与触发节点同一 PageNode（说明文档.md 条目 [27] 记录了根因与「三页合一」修复）；indexMainFrames（code.js:3021）已按 pageId → Frame 建索引并跳过 VARIANT_TAG / board/ / _components，天然支持多 Page 隔离。
为何重要
你已选定「与骨架并存」。而跨 Page 跳转不可用意味着「并存」不能是「一半在旧页一半在新页」—— 必须整套闭环搬过去。这条把该约束前置成架构决定，避免连线阶段才发现死链。
风险
  • 骨架页与高保真页会出现同名画框，findClickable（code.js:3095）的重名抛错逻辑会误伤，需按 Page 作用域收窄
  • 两页并存后文档与评审需明确「哪一页是评审对象」

ELEVATION Token + Figma Effect Style：消灭 9 处内联阴影

视觉与组件精修confidence 高complexity 低
做什么
参照现有 SPACING / RADIUS 的写法建 ELEVATION 常量表（card / modal / fab / pin 四档），把 9 处内联 effects 全部替换为查表；并注册为 Figma Effect Style，使设计侧可改。顺带把被改成描边的卡片阴影恢复为 PRD 规定值。
basis
direct: 阴影无集中 Token，9 处逐处内联 effects：code.js:822 / 1421 / 1446 / 1476 / 1537 / 1632 / 1703 / 2847；PRD §1 规定卡片阴影为 0 2 8 rgba(0,0,0,0.04)，现实现被替换为描边；PRD.md:159-171 已给出间距圆角 Token 体系（生成器已落地为 SPACING / RADIUS），阴影是唯一漏网的一类。
为何重要
高保真最直观的观感差异来自层次感。9 处内联意味着任何一次阴影调整都是霰弹式修改，在 4 天窗口内会反复出错；Token 化后一处改全局生效。
风险
  • Effect Style 名称一旦被设计侧改写，生成器按名查找会失败（须走「找不到即报错」而非兜底）
  • 描边改阴影后，Auto Layout 的视觉外边距会变化，需复核间距

MOTION 表驱动：让 §1.4.8 五行动效真的可点出来

交互与动效落地confidence 中高complexity 中
做什么
把 PRD §1.4.8 动效全表抄成 MOTION 常量（每行含 transition 类型 / easing / duration），在 proto_wire / proto_change_to / proto_overlay 调用处按场景查表传参，替换当前统一的 SMART_ANIMATE / EASE_OUT / 0.3s；模态用 overlay 语义、列表用 scroll 语义、返回用 proto_back。
basis
direct: PRD.md:191-200（§1.4.8）给出动效规范五行全表，而生成器只落地了单一 SMART_ANIMATE / EASE_OUT / 0.3s；本机 figma-prototype-mcp 已具备 proto_overlay / proto_scroll / proto_back / set_frame_scroll 等分场景工具（已核对 24 个工具）。
为何重要
「可点击」和「像成品」之间的差距主要就是动效语义。模态用页面跳转而非 overlay，评审时会明显感觉出戏；而这一层几乎不需要重画视觉，是性价比最高的保真度提升。
风险
  • 动效改动无法用 list_reactions 之外的手段验证，逐节点核对成本随连线数线性上升
  • overlay 与现有「模态即独立画框」的建稿方式冲突，可能要重建 3 个模态

状态矩阵自动建框 + 命名契约，缺一格即报错

状态覆盖矩阵confidence 中complexity 中高
做什么
声明一张「页 × 状态」矩阵（五大 P0 页 × 六类状态的适用子集），生成器遍历矩阵建框，画框名按 <page>/<state> 契约命名；生成结束时用矩阵反查，任一格缺失直接抛错而非静默跳过。
basis
direct: 现有状态覆盖是零散数组而非矩阵 —— 批次 2 的 22 画框中过程态 6 + 降级态 3 + 半径档 4，且 PRD.md:985（无权限）与 PRD.md:1320（已下架）无对应画框；PRD.md:971-980（§6.4.4）定义了兜底过程态六行时间轴。项目已沉淀「任何找不到就兜底的写法都要删掉，失败必须可见」（说明文档.md 条目 [30]）。
为何重要
状态遗漏是评审后返工的第一大来源，而人工清点 22+ 画框不可靠。矩阵化把「有没有画齐」从人的注意力问题变成程序断言。
风险
  • 矩阵子集判定本身需要人工决策（哪页该有哪状态），错误的矩阵会制造假安全感
  • 画框数量可能从 22 涨到 40+，SECTION_Y 布局与画布可读性需重排
  • 4 天窗口内可能挤占视觉精修时间 —— 建议排在想法 1、2 之后
