## 1. 为什么必须办

- **缺凭据的当前后果**：服务端 `PushSenderRegistry` **路由表为空** ⇒ 下发路径走「无发送器 → 仅站内兜底降级」。用户**不会收到任何弹窗**，只能在 App 内通知中心看到。**线上现在就是这个状态。**
- **工程取向已定**：本次不提供「记日志的假 Sender」（同 `DevOssClient` 被否决的取向）——假实现会把「已接入」的假象留在工程里。因此**必须凭据到位，才能写真实 Sender**。
- **凭据是厂商侧身份**：厂商推送服务器靠这对密钥判断「你是不是该 App 的正规开发者」，没有它无法下发。
- **6 家的由来**：iOS 只有 Apple 一家（APNs）；境内安卓被 5 家厂商分割（华为/小米/OPPO/vivo/荣耀），Google 的 FCM 境内不可用（契约枚举保留 `fcm` 仅作对齐）。

## 2. 我们要收集什么（统一产出物登记表）

**服务端凭据 = 只给后端用，必须走环境变量注入**（与 OSS / 通义千问 key 同一路径：`deploy/env/.env.*` + 容器注入）；**严禁入 git、严禁入镜像**。
与既有 `s2s.sms.whitelist` 直写配置中心 yml 的做法不同：那条是**手机号**（用户已裁定可接受入仓库），本条是**服务端密钥**，两者不可类比。

| 通道 | 服务端凭据（后端要） | 客户端凭据（App 内） | 从哪里取 | 状态 |
| --- | --- | --- | --- | --- |
| APNs | `.p8` 文件 + **Key ID** + **Team ID** + Bundle ID（即 topic） | 无（iOS 系统通道） | Apple Developer → Keys / Membership | ⬜ |
| 华为 | **App ID** + **App Secret** | `agconnect-services.json` | AGC → 项目设置 → 常规 → 应用信息 | ⬜ |
| 荣耀 | **App ID** + **App Secret** | `mcs-services.json` | 荣耀推送服务列表 → 应用信息（细节**待核实**） | ⬜ |
| vivo | **appId** + **appKey** + **appSecret** | 客户端 SDK 初始化用同组值 | 推送平台「应用信息」页 | ⬜ |
| 小米 | **AppSecret** | **AppId + AppKey** | 推送运营平台 → 应用管理 → 应用信息 | ⬜ |
| OPPO | **AppKey** + **MasterSecret**（名称**待核实**） | AppKey | OPPO 开放平台推送服务 | ⬜ |

**通用前置（华为/荣耀/小米都要，现在就能产出）**：**签名证书 SHA-256 指纹**。
取法（与 P7 已记录的取法一致）：

```bash
keytool -list -v -keystore <发布签名 keystore 路径> -alias <alias>
```

**固化值（务必与既有口径一致，不一致会导致设备注册失败）**：

| 项 | 当前值 | 说明 |
| --- | --- | --- |
| 包名 | `com.s2s.zhaoyazhao.dev` | **开发期临时值**；换正式包名须同步到全部厂商重新登记（见 B2-6a 任务书决策点②） |

### 3.1 华为 AppGallery Connect（✅ 现在就能办）

**为什么必须做**：境内华为设备量大；且**自分类权益申请有审核周期**（见 §5），是本组里最该先动的一家。

**是否要求上架**：**否**。官方 FAQ 原文：*"Can I use Push Kit for my app that has not been released to HUAWEI AppGallery? **Yes, you can.**"*（建议尽早发布以获得更好体验，但非前置条件）。

**办理入口**：https://developer.huawei.com/consumer/cn/ （AGC：https://developer.huawei.com/consumer/cn/service/josp/agc/index.html）

**前置依赖**：P1 执照（已完成）→ 华为开发者账号**实名认证**（企业）

**操作步骤**

**① 前置（一次性）**
1. 注册华为开发者账号并完成**企业实名认证**（[实名认证怎么做](https://developer.huawei.com/consumer/cn/doc/start/registration-and-verification-0000001053628148)）。
2. AGC 建**项目** → 建**应用**：应用名 `找鸭找` + 包名 `com.s2s.zhaoyazhao.dev`（[创建项目](https://developer.huawei.com/consumer/cn/doc/distribution/app/agc-help-createproject-0000001100334664) / [创建应用](https://developer.huawei.com/consumer/cn/doc/distribution/app/agc-help-createapp-0000001146718717)）。

**② 配指纹**（官方指引：[配置 AppGallery Connect](https://developer.huawei.com/consumer/cn/doc/development/HMSCore-Guides/android-config-agc-0000001050170137)）
3. **值已替你产出，直接复制即可**（本地复核命令：`keytool -list -v -keystore <发布证书> -alias s2s-release` → 取 `SHA256:` 那一行）：

   ```
   4E:FB:8B:21:9F:89:7D:42:B5:1B:7D:8F:B4:F7:C7:61:16:C8:DC:F3:C5:D0:65:47:57:FD:02:E3:CD:20:5C:FA
   ```

4. **在 AGC 里登记**：登录 AGC →「开发与服务」→ 项目列表选中项目 → **点进去选「应用」**（⚠️ 别停在项目层）
   → 「**项目设置 > 常规**」→ 在「**应用**」区域找「**SHA256 证书指纹**」→ 点右侧「**添加证书指纹**」→ 粘贴上值 → 「**保存**」。
   - 格式以**输入框校验提示为准**（通常是大写十六进制带冒号，即上面这一形态；若报格式错，去掉冒号再试）。
   - 指纹是**应用级**：每个应用各配一条；支持多条，本项目只需**发布证书**这一条（**别填 debug 证书**）。

**③ 设数据处理位置**（指引：[数据处理位置](https://developer.huawei.com/consumer/cn/doc/agc-data-storage-location)）
5. ⚠️ **先确认你在哪套控制台** —— 华为现役**两套**，菜单与路径都不同，**以页面实际菜单为准**：

**④ 开通推送服务**
8. 入口**两套控制台不同，以页面实际为准**：

10. 官方下一步：在「**推送服务 > 配置**」页签按提示**开通精准推送服务**（官方括注：精准推送 = **订阅用户 / 受众群组 / AB 实验**，需指定数据存储位置）。本项目推送场景**不用受众群组 / AB 实验** ⇒ **页签标为必开则开、非必开可跳过，以 AGC 实际页面提示为准**。
11. 取凭据：在「推送服务 > 配置」拿 **App ID / App Secret**（给后端）；在「项目设置 > 常规 > 应用」下载 **`agconnect-services.json`**（给客户端）。
   - ℹ️ **「OAuth 2.0 客户端 ID（凭据）」= 应用级通用凭据**（**订正**：早前记为「属华为帐号服务、不是推送凭据」**有误**）：**App ID 即 Client ID**（本项目实测同值 `119380529`），**Client Secret 即 App Secret** —— **Push Kit 服务端换 token 用的正是这一对**（`grant_type=client_credentials`）。本项目登录虽不走华为帐号服务，但**不影响**这对凭据用于推送；其「**回调地址**」与推送无关，**无需填写**。
   - 下载 `agconnect-services.json` 时建议**打开「不包含密钥」开关**（该文件要进客户端工程，避免密钥随仓库扩散）；确需带密钥时按 §7 规则处理，**禁入 git**。
   - 🔒 **Secret 已在截图中多次出现 ⇒ 采取「先重置、后配置」顺序**：先在应用页**重置 Client Secret**（旧值立即作废），**再把重置后的新值**写入服务端。⚠️ **顺序不可颠倒** —— 若先配好再重置，服务端会当场失效。
   - 🆕 **新版控制台捷径（实测）**：应用「**基础信息**」页直接显示 **APP ID** 与「**OAuth 2.0 客户端ID（凭据）：Client ID / Client Secret**」，无需另去「推送服务 > 配置」页找（该页可互核，两处应一致）。

**材料硬指标**：企业实名认证材料；SHA256 指纹须与**实际打包证书一致**。

**驳回雷点**
- ❌ **指纹填成 debug 证书或其他证书** → 设备注册推送失败（须与**实际发布打包证书**一致）。
- ❌ **同一包名被别的账号占用过** → 开通推送会报「无应用存在」；须先在原项目**禁用**推送服务，或走**应用转移**。
- ❌ **应用类型建错 / 包名填错对象**（本项目实际踩坑）→ **本期只需建「Android应用」一条**（APK 走 HMS Push）；**同一项目下包名不可被两条应用共用** —— 若把 `com.s2s.zhaoyazhao.dev` 填给了「HarmonyOS应用」，Android 那条就填不上包名（**包名为空的 Android 应用收不到推送**）。**处置顺序**：① 先试**改 HarmonyOS 应用的包名**（能改则无需删除）；② 不能改则**删除该应用**；③ 回到 Android 那条补包名。**官方依据**：「**下架应用仍会占据包名，只有删除应用才会释放包名**」；官方问答「彻底删除后即可重新上传」⇒ **删除即可复用该包名**。**删除入口** = 应用「**分发 > 应用上架 > 应用信息**」页**底部**「删除应用」。**前提** = 状态不属于「已上架 / 正在审核 / 下架处理中」（本项目为「准备提交」⇒ 符合，无需申诉）。⚠️ 官方提示「删除应用后 AGC 会关闭该应用已开通的服务」—— 那是**应用级**；**推送服务为项目级**，删后回推送页确认仍开通。⚠️ **别删错条**（保留 Android 那条，其上有 APP ID 与已配指纹）。若补包名时仍报占用，先等待释放，持续失败则**提在线工单**（官方 FAQ 指定处置）。
- ⚠️ **数据处理位置**：官方两处措辞不同 —— Android 文档写「导致推送消息**下发时延增加**」，HarmonyOS 文档写「**无法下发**」。本项目只能选「中国」，不构成选择问题；但**不要事后改**（见上第 7 条）。
- ❌ 不申请自分类权益 → 默认按**资讯营销类**，**每天仅 2 条或 5 条**（见 §5，与本项目 `DAILY_LIMIT = 10` 冲突）。
- ℹ️ 推送服务权益是**项目级**：同一项目再加应用无需重复开通；但**证书指纹是应用级**，逐个应用配。

### 3.5 OPPO 推送（⛔ 等上架，且无例外通道）

**是否要求上架**：**是**。通知栏推送要求「应用需在 OPPO 软件商店上架」。
**例外通道不适用**：OPPO 提供「**应用不上架申请（推送服务环节）**」，但**仅开放国内政府类、企业内部 IM 类应用** ⇒ **本项目（UGC 供需信息平台）不符合，不必尝试**（提交即被驳，白耗 5 个工作日）。

**办理入口**：https://open.oppomobile.com/ （推送服务在「应用服务 > 开发服务 > 推送服务」）

**前置依赖**：**企业开发者**认证（管理员身份证 + 企业名称 + 营业执照 + 法人姓名 + **对公银行账户**）；个人开发者**无 push 权限**

**操作步骤**（上架后执行）
1. 注册 OPPO 账号 → 认证**企业开发者**：
   - 有对公账户 → 走**对公打款**（打入 0.1–0.99 元随机金额，**72 小时内**回填，**3 次机会**）；
   - 无对公账户 → 走**人工审核**（执照照片 + 法人身份证号 + 法人手持身份证照片，**1–3 个工作日**）。
2. 创建应用并**上架** OPPO 软件商店。
3. 「推送服务」→ 选中应用 →「**申请开通**」→ 提交（平台 **1 个工作日**返回结果）。
4. 审核通过后取服务端凭据（名称待核实）。

**材料硬指标**：营业执照、法人姓名、对公账户（或人工审核替代材料）。

**驳回雷点**
- ❌ 用个人开发者账号申请 → **无 push 权限**。
- ❌ 指望「不上架」例外通道 → 仅政府类/企业内部 IM，本项目不适用。
- ⚠️ 对公打款 72 小时超时 → 金额失效，需重新申请打款。

**产出物**：AppKey + MasterSecret（名称待核实）。
**状态**：⛔ **等上架解锁**

### 3.6 APNs / Apple（🔴 卡在账号，iOS 侧关键路径）

**为什么必须做**：iOS 唯一通道，没有替代。

**是否要求上架**：不适用（无商店前置）；但**必须有 Apple 开发者账号**——**本项目当前尚无**（2026-10-16 确认）。

**办理入口**：https://developer.apple.com/account/resources （账号：https://developer.apple.com/programs/）

**前置依赖**：Apple 开发者账号（**Organization 类型**，UGC 类不可用个人账号）；组织账号需 **D-U-N-S 编码**（免费申请，**1–2 周**）

**操作步骤**
1. **先办 D-U-N-S 编码**，再申请 **Organization** 类型 Apple 开发者账号（见 P8 步骤 2）。
2. 账号需具备 **Account Holder 或 Admin** 角色（生成密钥的硬要求）。
3. Certificates, Identifiers & Profiles → **Keys** → **+** → 填 Key Name。
4. 勾选 **Apple Push Notification service** → **Configure** → 选环境配置与密钥类型（Team Scoped / Topic Specific）→ Confirm。
5. **Download** → 得到 `.p8` 文本文件。
6. 记录 **Key ID**（Keys 页面）与 **Team ID**（Membership 页）。

**材料硬指标**：企业组织信息（与 D-U-N-S 一致）。

**驳回雷点**
- ❌ **`.p8` 只能下载一次**：密钥**不保存在账号里**，下载按钮变灰即表示已下载过 ⇒ **下载后立即异地备份 + 入密码管理器**，丢了只能重新生成（旧密钥作废，服务端要同步换）。
- ❌ 用个人账号承载 UGC 类 → 上架阶段会被拒；**组织账号与 D-U-N-S 是长腿，越早启动越好**。

**产出物**：`.p8`、Key ID、Team ID。
**状态**：🔴 **未启动（无账号）**

## 5. 华为自分类权益：必须申请，否则默认 2–5 条/天

- **不申请的后果**（官方原文）：未开通自分类权益时，Push Kit **默认你推的是「资讯营销类」消息**，而资讯营销类**每天只能发 2 条或 5 条**（按应用类型）。
- **与本项目的冲突**：本项目口径是**单用户每日接收推送 ≤ `NfrPush.DAILY_LIMIT`（10 条）**（PRD §6.14 / §12.3）——**10 > 2/5，不申请即被通道侧卡死在 2 条**。
- **申请路径**：AGC → 开发与服务 → 项目 →「**增长 > 推送服务 > 配置**」→ 选应用 → **自分类权益「申请」** → 选消息发送类型 → 补充**消息示例**（订阅消息类型还需补场景说明与图片）→ 提交 → 可用「查看进展」跟进。
- **分类归属**：需按《华为消息分类标准》（服务与通讯 / 资讯营销两大类的二级分类）**逐条比对后选定**。本项目推送内容 = 「匹配到需求/资源的提醒」+ 互动通知。⚠️ **分类归属须对照官方标准确定，本清单不预设结论**（选错类别会导致提醒方式与额度都不对）。

### 5.1 本项目分类映射（申请材料草稿，2026-10-16 按官方原文逐条比对）

**官方 category 取值**（云端通知，**全大写**）：社交通讯 = `IM` / `VOIP` / `MISS_CALL`；服务提醒 = `TRAVEL` / `HEALTH` / **`WORK`** / **`ACCOUNT`** / `EXPRESS` / `FINANCE` / `DEVICE_REMINDER` / `MAIL` / `PLAY_VOICE` / **`SUBSCRIPTION`**；资讯营销类 = `MARKETING`。
**额度差异（关键）**：**服务与通讯类每日推送数量不受限**；资讯营销类**单个应用每日每设备 2 条或 5 条**。

| 本项目推送内容 | 建议类别 | category | 官方场景依据 | 结论 |
| --- | --- | --- | --- | --- |
| 实名/资质**认证审核结果** | **工作事项提醒** | `WORK` | 「待处理业务流程…**审核进度提醒、认证状态流程提醒**」 | ✅ **明确可归** |
| 账号 / 认证**状态变化** | **账号动态** | `ACCOUNT` | 「账号信息认证等」 | ✅ **明确可归** |
| **有人收藏 / 联系你**的信息 | **订阅**（社交动态类） | `SUBSCRIPTION` | 社交互动提醒含「**被收藏**、留言、评论」 | ⚠️ **需满足订阅流程要点**：① 应用设置需有**独立消息开关**（本项目设置页已有通知开关四项）；② 推送**标题/正文须含**「订阅/预约/关注/好友/粉丝」等字样 |
| **匹配结果提醒**（「附近有人发布了与你相关的需求」） | ❌ **官方无对应场景** | — | `SUBSCRIPTION` **仅开放列明场景**（直播开播/预约活动/签到打卡/商品降价/特别关注作者动态/行情/付费订阅/主动订阅专题/社交互动），**匹配提醒不在其中** | ⚠️ **需产品裁定**（见下） |

**建议（待确认）**：
- **先申请 `WORK` + `ACCOUNT`** —— 与本项目认证/审核通知明确吻合、无解释空间，可立即提交
- **`SUBSCRIPTION`** 视产品是否愿意补「关注 / 订阅」能力再定（否则文案与流程要点对不上）
- **匹配结果提醒**：内测期可暂按 `MARKETING`（2 条/天）或**完全走站内通知兜底**；若要解锁额度，须产品侧调整（把它做成「**用户关注的分类/关键词有新结果**」并补订阅流程）

⚠️ 官方明示：**分类错误的，将暂停或取消自分类权益**，且服务通讯类消息不再加快发送 ⇒ **宁可少报类别，不要错报**。

> 📄 **申请材料已成文（可照抄提交，供后期查阅）**：[华为推送自分类权益申请材料.md](file:///d:/developer/code/aicoding/s2s/docs/华为推送自分类权益申请材料.md) —— 含**工单模板**（入口不可达时的处置）、拟申请类别与官方依据、**可照抄的消息示例与场景说明**、暂不申请项（匹配提醒）、备选订阅类要点、**申请通过后的代码衔接**（`category` 映射）。
> ⚠️ **入口现状（2026-10-16 实测）**：华为改版后，新版 HarmonyOS 开发者中心「API管理」仅有推送服务**开关**，「配置」页签不存在；官方文档所述老路径「增长 > 推送服务 > 配置」已不可达 ⇒ **列挂账、提工单问入口**；**不申请仍可推送（限 2 条/天）⇒ 不阻塞开发**。

## 7. 交接格式：凭据怎么给到代码侧

- **服务端凭据**：写入 `deploy/env/.env.<环境>`（与 `DASHSCOPE_API_KEY` 同路径），由容器注入；**禁入 git、禁入镜像、禁贴聊天记录**。
- **变量命名**：建议 `S2S_PUSH_<通道>_<字段>`（如 `S2S_PUSH_HW_APP_ID`）；⚠️ **最终命名在实现 `PushSender` 时确定**，本清单只给方向，不预设设计口径（守「不新增口径」红线）。
- **客户端凭据**：`agconnect-services.json` / `mcs-services.json` 属**可入工程的配置文件**（厂商设计如此），但仍须确认是否含敏感字段后再入 git。
- **`PushSender` 实现顺序建议**：先做**能立刻拿到凭据**的通道（华为 → 荣耀），再补 vivo（测试模式可先联调），最后是小米/OPPO（等上架）。**每接一家即真机实测一次**，避免「一次接六家最后一起排错」。
