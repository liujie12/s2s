## 0. 产品总览

### 0.1 一句话定义

> **找鸭找 = 5 公里生活圈 · 双向供需信息共享 APP，AI 智能匹配 + 智能发布 / 地图分类图层快加载 / 信息完整度三档分级管理**（四目标联动一句话）
> 资源方与需求方双向发布，平台做就近匹配与信息共享，交易在线下达成。四大目标（T1 AI 匹配 / T2 AI 智能发布 / T3 分类图层快速加载 / T4 信息完整度三档）在产品定位层面集成。

### 0.2 北极星指标

> **纯信息北极星三乘积 = AI 匹配召回率 × 分类图层加载成功率（P95≤300ms） × 🟢 完整发布率**（目标 ≥0.216）

**三轴口径定义**：
- **AI 匹配召回率** = 用户发布需求后 5min 内被推送到 Top20 资源方中至少 1 个资源方点击查看该需求详情的比例（依赖 S1 双向推送引擎 + T1 LR+GBDT 模型）
  - **分母生效条件**：仅当该需求"同城 + 同二级类目"在库有效资源 ≥20 条时，本次发布才计入分母；不足 20 条的发布**不计入召回率**，单独归入「供给不足占比」作为冷启动观测指标（不参与乘积计算）；
- **分类图层加载成功率** = 用户切换分类 Tab/二级类目/三级类目后，地图 Pin 首屏渲染 P95 耗时 ≤300ms 的会话占比
- **完整发布率** = 发布完成时即满足 🟢 完整档（必填 100% + 位置到门牌号 + 三级类目精准命中）的发布条数 / 总发布条数

**目标线**：0.6 × 0.6 × 0.6 = 0.216（三轴等权硬线，任一轴为 0 → 整体为 0）

> **0.6 与 0.216 的性质**：这是**首版拍定基线，非已验证目标**，无历史数据支撑。Batch1 上线后第 4 周用实测三轴分布做一次校准，校准结论同步更新本节与 BRD 对应条目；校准前不作为对外承诺。

#### 0.2.1 D1 决策兜底：等权硬线 + Batch1 冷启动观察期

> **决策 D1**：全期统一 0.6×0.6×0.6=0.216，等权相乘，任何一轴为 0 → 整体为 0。

**理由**：战略叙事最强，团队聚焦无歧义，"乘积飞轮"核心论点保留完整（任何一轴为 0=产品失败）。

**识别风险**：Batch1（2026-08-24 → 09-30）AI 轴未上线 → 北极星恒 0，团队无考核指标可对齐。

**兜底方案**：
- Batch1（2026-08-24 → 09-30）设为"**冷启动观察期**"——北极星看板照样跑（AI 轴在冷启动阶段 0 规则加权期按实测值展示，未上线时填 0），但**不作为团队 KPI 考核**；
- 从 Batch2（2026-11-26 起，AI 推送 + 匹配模型按 §6.12 冷启动三阶段上线）开始正式纳入考核；
- AI 召回率口径同步定义为：**"用户发布需求后 5min 内被推送到 Top20 资源方中，至少 1 个资源方点击查看该需求详情的比例"**（依赖 S1 双向推送 + T1 匹配模型，Batch2 上线后可测；分母生效条件见 §0.2）。

# 第一部分：视觉设计系统

## 1. 视觉设计系统（Visual Design System）

### 1.1 功能名

视觉设计系统（鸭子 IP 重设计 + 色板/字体/组件/地图图层）

### 1.2 需求描述

在"找鸭找"品牌名与鸭子 IP 的基础上，建立一整套现代化、简约、丝滑的视觉规范，支撑极简丝滑体验定位，并让地图具备清晰的分类区分度。

### 1.3 概述

视觉设计系统必须覆盖以下五项，缺一不可：
- 统一色板与语义色（主/辅/成功/警告/错误/中性）；
- 统一字号、字重、行高规范；
- 组件级样式（按钮、卡片、表单、列表、导航）；
- 地图图层分类分色方案；
- 鸭子 IP 现代造型规范。

本章即前端工程化与 UI 走查的唯一基准。

### 1.4 相关页面设计（规范）

#### 1.4.1 品牌与 IP

| 项 | 规范 |
|---|---|
| 品牌名 | "找鸭找" 保留 |
| 鸭子 IP 气质 | 现代、圆润、亲切；减少卡通感，提升几何化与抽象度；主色与品牌主色一致 |
| Logo 构成 | 鸭子符号 + 品牌名文字，横排 / 竖排 / 单符号 三种版 |
| 禁用 | 不允许在 IP 上叠加复杂渐变、阴影、花纹 |

#### 1.4.2 色板

品牌主色三色已定稿，其余中性/语义色沿用下表取值。

| 色名 | 用途 | HEX |

| 辅助色 Accent | 辅助强调、分类点、需求态 | `#FF8A3D` |
| 成功色 Success | 认证通过、发布成功 | `#22C55E` |
| 警告色 Warning | 提示、待完善 | `#F59E0B` |
| 错误色 Error | 失败、禁用、举报 | `#EF4444` |
| 文字 Primary Text | 标题、正文主色 | `#1F2937` |
| 文字 Secondary Text | 次要文字、说明 | `#6B7280` |
| 文字 Placeholder | 输入占位、提示 | `#9CA3AF` |
| 分割线 Border | 卡片分割、边框 | `#E5E7EB` |

| 类型 | 样式 | 主用途 |
|---|---|---|

#### 1.4.7 卡片组件规范

- 白底（Surface）+ R-lg + 阴影（0 2 8 rgba(0,0,0,0.04)）；
- 内边距 lg（16）；
- 内元素间距 sm；
- 卡片按状态：正常 / 选中（加 Primary Light 边框）/ 下架（Opacity 50% + "已下架"标）。

#### 1.4.8 动效规范（丝滑体验基础）

| 场景 | 规范 |
|---|---|
| 页面切换 | 右侧滑入（前进）/ 左侧滑出（返回），260ms，ease-out |
| 弹窗/抽屉 | 底部上滑，240ms，spring；遮罩渐显 180ms |
| 按钮反馈 | 按下缩放 0.97，80ms，释放回弹 |
| 地图 Marker | 首次出现渐入 + 轻微上浮；点击弹出信息窗弹跳 |
| 列表加载 | 骨架屏占位 → 内容淡入 180ms |
| 发布成功 | 成功 toast + 主色确认勾动画（Lottie 可用 Lottie） |

### 1.5 用户旅程

本章为规范层，跨全部业务模块适用，视觉一致性沿用户主链路逐点验收：

U1 首次打开：启动页鸭子 IP → 登录页主色按钮 → 首页地图分类分色 Marker，全程色板、字号、圆角一致，无风格跳变。

U2 发布链路：分类选择器 → 模板表单 → 提交成功动效，输入框、标签、按钮均取自同一组件规范，动效时长统一 200–300ms。

U3 浏览链路：地图 → 列表卡片 → 详情页，卡片阴影、间距、面包屑样式一致；加载态统一用骨架屏，空态统一用鸭子 IP 缺省图。

### 1.6 用户故事

- As a **本地居民**，I want **界面清爽、层级一眼看懂**，So that 我不用学习就能完成找人找活。
- As a **需求方**，I want **地图上按颜色区分类目**，So that 我在 5 公里内快速锁定目标类型。
- As a **UI 设计师**，I want **色板/字号/间距/圆角/组件有唯一冻结基准**，So that 出稿不反复返工、走查有明确依据。
- As a **前端工程师**，I want **规范以 Design Token 形式交付**，So that 我按常量实现，不靠目测取色写死样式。

### 1.7 实现逻辑

- 前端工程化：以 Design Token 形式落地（色/字号/间距/圆角为常量）；
- 组件库：按钮、卡片、输入框、标签、空状态、骨架屏为基础必做组件；
- 鸭子 IP 素材：SVG 矢量（Logo、启动图、空状态、缺省图）；
- 暗色模式：本期不强制，但色板设计时考虑未来适配。

### 1.8 功能细节描述

- 颜色对比度：主色/文字满足 WCAG AA（正文 ≥ 4.5:1）；
- 可访问性：按钮最小触控区 44×44 px；
- 国际化：本期不做，但字符串全部抽出不硬编码；
- 品牌资产最终须经设计稿评审冻结，不得随意改动颜色/圆角值。

# 第二部分：分类体系

## 2. 多级分类体系（参考 58 结构 · 自定类目）

### 2.1 功能名

多级分类体系（5 大类 × N 中类 × M 小类，分类分色地图 Marker）

### 2.2 需求描述

建立覆盖"工作/房屋/生活/服务"等关键生活圈场景的多级分类体系。参考 58 的多级树结构并为 5 公里生活圈裁剪，形成清晰的 5 大类、三级树结构。分类体系直接驱动：地图 Marker 颜色、发布模板、筛选、搜索分类匹配。

### 2.5 资源态 vs 需求态

同一三级类目下，发布时可选"资源"或"需求"。地图 Marker 视觉区分：

| 类型 | Marker 样式 |
|---|---|
| 资源（可供给） | 对应大类颜色**实心**圆点 + 小图标（见 §6 地图图层） |
| 需求（求购/求助） | 对应大类颜色**空心**圆点 + 内部 "?" 标记 + 轻微描边 |

### 2.6 相关页面设计

- **首页分类栏**：一级分类横滑 Tab + 资源/需求切换开关（胶囊）；
- **发布页分类选择**：三级树级联选择器（先选大类，再选二级，再选三级）+ "当前选择"面包屑；
- **列表页筛选栏**：一级分类 Tab + 二级筛选项；
- **首页搜索态**：导航栏搜索框输入关键词 → 经同义词映射命中分类子树 → 地图图层按命中分类过滤（详见 §6.4.1「导航栏搜索框口径」）。**不是独立页面**，故 §10.1 页面清单不含搜索页；
- **详情页**：分类面包屑（工作 > 全职招聘 > 餐饮服务）。

### 2.7 用户旅程

U1 发布时选分类：进入发布 → 选大类 → 选二级 → 选三级 → 自动加载对应模板 → 填充字段。

U2 浏览时按分类筛选：首页一级分类 Tab → 列表页二级筛选 → 详情页分类面包屑。

### 2.8 用户故事

- As a **本地居民**，I want **发布时能快速定位到三级分类**，So that 系统给我匹配对路模板、详情字段和用户。
- As a **需求方**，I want **地图上一眼区分资源和需求**，So that 我不浪费时间看混淆的 Marker。
- As an **运营**，I want **分类后台可增删改**，So that 类目可随市场变化调整，不用发版。

### 2.9 实现逻辑

- 分类以结构化数据存储（前端静态 JSON + 运营后台接口），版本号 + 本地缓存；
- 每个叶子类目绑定 1 套发布模板（见 §5）、1 组详情页字段、1 个大类色；
- 分类搜索支持拼音首字母、同义词映射（"保洁"↔"家政"）；
- **强制资质类目**（详见 §4 认证）：在分类树上加标记，叶子类目为 "高敏" 时发布必须已通过对应资质认证。

## 3. 注册 / 登录 / 个人中心

账号体系（注册、登录、个人中心、设置、实名与资质认证）

### 3.6 用户故事

- As a **新用户**，I want **一条验证码就能登录注册**，So that 我不被"先注册后登录"拦在门外。
- As a **用户**，I want **看别人的信息能看到实名标和资质标**，So that 我能判断谁可信。
- As a **高敏类目服务者**，I want **上传资质获得专属标**，So that 我比普通发布者更具信任感。
- As a **用户**，I want **我设置的默认范围（3km）能被记住**，So that 每次打开不用再调。

### 3.7 实现逻辑

- **登录方式**：短信验证码主方案（合并注册/登录）；账号密码保留；
- **会话 Token**：JWT / 自有 Token，有效期 30 天，自动续期；
- **隐私**：手机号默认脱敏展示（138****8888），仅在用户显式授权"联系 TA"时跳转外呼；
- **注销账号**：保留 7 天冷静期，不可立即删；
- **基础实名权限两档（T4 Scope 校正）**：
  - ❌ **未实名**：每日最多看 3 条详情（防爬）；**发布走"先发后审"受限态**（见下）；
    - **额度耗尽拦截态**：点第 4 条详情时不进入页面，弹半屏引导——标题"今天的 3 条看完了"，正文"完成实名后可无限查看"，按钮「去实名（约 30 秒）」+「明天再来」；返回原列表页，不留空白页；
    - **未实名发布（先发后审受限态，冷启动供给保护）**：发布流程完整走通、内容入库，但落地为受限态——
      - 强制标 🔴 档，**不进 AI 推荐池**（不参与 §6.12 匹配召回）；
      - **联系方式对外完全隐藏**，他人详情页显示"发布者实名后可联系"；
      - 每日最多发 1 条，未实名累计在库受限条目上限 3 条；
      - 发布成功页直接引导实名：主按钮「立即实名，让别人能联系我（约 30 秒）」+ 次按钮「稍后」；
      - **24h 内完成实名** → 该条自动转正常态（完整度重算、进推荐池、联系方式按 §7.4.2 展示）；**24h 未实名** → 该条自动隐藏（不删除），实名后可一键恢复；
  - ✅ **实名**：发布无限次 + 看详情无限次 + 正常进推荐池；
  - 仅此两档，**无五级阶梯、无 DAU 触发、无商业化分级**；
- **举报与下架**：统一走 §9.10.3 举报分级响应引擎（累计风险分 ≥60 自动下架 + 人工复核），本节不另设举报率阈值。

## 4. 实名认证与资质认证

### 4.1 功能名

实名认证（个人）+ 资质认证（B 端/高敏类目）

### 4.2 需求描述

建立平台的基础信任机制。**信任信号 = 实名标（全量）+ 资质标（高敏类目强制）+ 信息完整度三档 🟢🟡🔴（每条发布自动判定，T4）**。

**明确不做（T4 Scope 红线）**：发布记录数加分、举报率信誉衰减、统一信誉分、动态权重回归——纯信息平台只做信息本身的真实性 + 完整性信号，不做人的信誉评级。

### 4.3 概述

| 认证类型 | 对象 | 方式 | 必选场景 |
|---|---|---|---|
| **个人实名** | 所有 C 端用户 | 身份证二要素（姓名+身份证号）+ 手机号一致性 | 强推荐，非强制（未实名每日仅看 3 条详情，发布落"先发后审"受限态，详见 §3.7） |
| **个人资质** | 特定服务者（家政/维修/教学等） | 证书 OCR + 人工审核 | 发布服务类 5.x 叶子类目强制 |
| **企业认证** | B 端用户（房东/商家/招聘企业） | 营业执照 OCR + 工商三要素核验 | 发布房源/工作招聘等强制 |
| **车辆认证** | 车辆相关发布者 | 行驶证 OCR | 发布拼车/租车强制 |

| 步骤 | 操作 | 反馈 |
|---|---|---|
| 1 | 进个人中心 → 信任与认证 → 点击"个人实名 · 去认证" | 打开认证页 |

- As a **找家政的用户**，I want **看见服务者挂了"家政资质✅"**，So that 我敢联系上门。
- As a **王师傅**，I want **我的维修资质成为"官方标"**，So that 别人比相信无标陌生人更相信我。
- As a **小店**，I want **完成企业认证后可发布招聘**，So that 平台允许我发而不是被拦截。

### 4.7 实现逻辑

- 二要素、三要素、OCR：接第三方核验服务（需在 MRD 外部依赖里对齐供应商）；
- 人工审核：后台运营工作台（不在本期前端 APP 内开发，但 PRD 定义后台审核字段与 SLA）；
- 认证数据存储：身份证号**只存不可逆哈希 + 后 4 位明文**（用于用户自查与客服核对），**不存完整明文**；姓名加密保存；OCR 原照加密后 7 天删除；APP 端仅展示状态与脱敏星号（与 §9.6 数据最小化同一口径）；
- **每日发布限制**：未实名用户每日 1 条且落受限态（🔴 档 + 不进推荐池 + 联系方式隐藏，在库上限 3 条，24h 未实名自动隐藏）；实名用户不设限（但仍受 §9.10.3 举报下架规则管，详见 §3.7 基础实名权限两档 T4）。

### 4.8 功能细节描述

| 边界 | 规则 |
|---|---|
| 二要素 3 次失败 | 锁 24h，需人工申诉 |
| 同一身份多账号 | 一个身份证最多绑定 2 个账号 |
| OCR 识别失败 | 支持手动重填字段 + 人工复核 |
| 资质有效期 | 年审到期前 30 天提醒，超期自动打"待补"标，不可继续发高敏类目 |
| 累计风险分 ≥60 触发复核 | 自动下架 + 推送通知给本人 + 运营待审列表（唯一口径见 §9.10.3） |

### 5.6 用户故事

- As a **新用户**，I want **模板告诉我该填什么**，So that 我不尴尬不知道怎么描述。

### 5.7 实现逻辑

- **模板引擎**：按叶子类目 ID 映射模板 Schema（字段 key、label、类型、校验、placeholder、默认值、是否必填、单位选择）；
- **记忆机制**：按 "user_id + category_leaf_id" 维度存最近一次发布值，写入本地缓存 + 云端；下次进入同一分类时先拉取云端（优先），本地作 fallback；
- **价格单位**：模板 Schema 里定义 price_units 数组（如 `["元/小时","元/次","元/㎡","面议"]`），前端自动渲染切换；
- **地图选点**：`map-selector` 组件，配色遵循 §1 视觉系统；
- **有效期**：全平台统一默认 7 天，模板不可覆盖（避免多套口径）；
- **资源/需求切换**：写入 post.type = 'resource' / 'demand'，Marker 样式、详情页标题区受其影响；
- **强制认证拦截**：提交前调用接口，若 leaf_category.need_cert 非空且 user.certs 不包含 → 拦截并弹浮层跳认证。

### 5.9 T2 AI 智能发布四模式

**四模式发布**：

| 模式 | 描述 | 适用场景 |
|---|---|---|
| **① 多媒体 7 秒输入**（T2 主路径） | 拍 1 张图 + 说 1 句话 → AI 四件套自动猜测（标题/分类/价格/模板字段） | 老用户快速发布主路径 |
| **② 语音零键盘** | 全程语音输入，3B 小模型语音识别 + 生成 | 不便打字场景（开车/做饭/老人） |
| **③ 对话式一问一答**（S5） | 每屏 1 问，新手首选用 | 新用户首次发布引导 |
| **④ 抢发模式**（S5） | 只填标题 + 拍照就发布，系统猜其他字段，24h 内补全 | 急用场景"先发占位，再补全" |

**AI 解析失败与结果确认态（四模式共用）**：

| 状态 | 触发条件 | 界面表现与出路 |
|---|---|---|
| 解析中 | 提交后等待 AI 返回 | 骨架屏 + "正在识别…"，超过 5 秒显示"稍等，马上好"；可点"取消，手动填" |
| 解析失败 | 接口超时 / 3B 模型无返回 / 图片不可识别 | 停留原页，Error toast "识别没成功，可以重试或手动填" + 两个按钮「重试」「改为手动填写」；已输入内容全部保留 |
| 结果待确认 | AI 返回四件套后 | 强制进入确认页：逐字段展示 AI 猜测值 + "AI 猜" 角标，用户可逐项改；底部「确认发布」「全部重填」 |
| 用户拒绝结果 | 在确认页点"全部重填" | 清空 AI 猜测值，回到手动模板表单，不消耗当日 AI 配额 |
| 部分字段无法猜出 | Scope 四步管线判定不一致而拒绝注入 | 该字段留空并标"需你补充"，不猜、不编造；必填项未补齐时「确认发布」保持禁用 |

**配额消耗口径**：仅"结果待确认"页点击「确认发布」才计 1 次 AI 配额；解析失败与用户拒绝均不计。

**页面承载**：上述"结果待确认"态由独立页面 `ai-confirm-screen` 承载（见 §10.1）；点「确认发布」后进入 `publish-success-screen`。

**7 秒路径与 🟢 完整档的衔接（消除"快"与"全"的对立）**：

- **7 秒的口径**：指模式①的**用户输入耗时**（拍图 + 说一句话），**不含确认页耗时**；全文提到"7 秒/3 秒出稿"均按此口径理解；
- **确认页默认带 🟢 冲刺项**：确认页底部固定一个「再花 5 秒升 🟢」区块，只放 🟢 档差的两项——**门牌号**与**三级类目**：
  - AI 已猜出 → 展示猜测值 + 一键确认；
  - AI 未猜出 → 门牌号给「取当前定位门牌」快捷按钮，三级类目给最近 3 个候选的单选片；
- **达标即改角标**：两项补齐 + 必填 100% 时，「确认发布」按钮上方角标实时从 🟡 跳 🟢，文案"附近人 2 倍概率看到"；
- **不强制**：用户可直接「确认发布」跳过该区块，落 🟡 档并按 §5.11 的 1 小时引导继续追；
- **因此四模式与 🟢 完整率不互斥**：模式①②③走确认页冲刺，模式④（抢发）明确落 🔴 并按 §5.11 的 24h 规则处理。

### 5.10 严格 Scope 四步管线规格

**严格 Scope 四步管线规格**：

| 步骤 | 名称 | 规格 |
|---|---|---|
| **Step 1** | 用户输入 | 拍图 + 说话（≈7 秒） |
| **Step 2** | Scope 提取 | U（显填）∪ N（邻居众数）∪ P（平台已知）三集合实体交叉一致性校验 → 不一致拒绝注入 |
| **Step 3** | 3B 小模型生成 | Prompt 模板限死"仅用 {scope} 字段填入，禁止编造新实体" |
| **Step 4** | 逆向 Scope 比对 | 生成中每个实体都能在 scope 找到源头 = 合法输出 |

**配套机制**：

- **完整度门槛（T2）**：🔴 待补档不进 AI 推荐池，发布完成页直接提示"还差哪几项就能进推荐"；
- **AI 配额二维分层（T2）**：按「实名状态 × 完整度档」分配每日额度 —— 实名+🟢=20 次、实名+🟡=10 次、未实名或 🔴=3 次；高敏类目额外 +10 次。**不设人格化信誉分与等级标签**（对齐 Scope 红线）。

### 5.11 发布有效期管理

**发布有效期管理（全文唯一口径）**：

- **默认 7 天，不提供其他可选值**；
- **7 天一键刷新**：每 7 天弹"这条还在吗？点一下继续挂 7 天"，每次刷新续 7 天，可无限次刷新；
- **14 天不刷新自动从地图推荐池下架**（仍保留在列表页历史 + 个人中心可手动重发）；
- **重发有效期同为 7 天**；
- **发布后 1 小时内完整度提升引导**：🔴 待补 / 🟡 半完整 → 发布完成页直接显示"还差 2 张图 + 门牌号就能让附近更多人看到，30 秒补上"；
- **抢发 24h 未补全的后果**：到期仍为 🔴 待补档 → **自动退出 AI 推荐池，仅保留在列表页与地图按位置展示**（不删除、不下架）；同时推送一次"补全提醒"，补齐后即刻恢复进池；有效期仍按 7 天口径走，不因未补全而缩短；
- **明确不做**：撮合反馈收集、周度自适应权重回归（纯信息不追踪撮合，不跑成交数据驱动模型）。

| T3 弹层态 | 底部上滑弹层 + 40% 遮罩 | 按层级 40–70% 屏高 | 三级树下钻专用，见 §6.9 |
| 图例态 | 图例卡 | 约 50px | 由右上「?」按钮唤起，**不再常驻** |

- **为什么收起态保留摘要胶囊、而不是收干净**：控件一收，用户即失去「我现在筛的是什么」的反馈，会反复展开确认，操作成本反而上升。故收起 ≠ 隐藏，而是压缩为一行只读摘要（范围 + 供需 + 分类路径三项），点它即重新展开。这是「收起」与「可用」的唯一交点；
- **为什么图例不常驻**：图例是一次性认知（实心=资源、空心+?=需求），用户学会后无需每次看地图都复读，常驻属净损失；
- **为什么入口用 44×44 圆按钮而非细横条**：横条无论多薄都会横贯整屏、切断地图视野；圆按钮只吃一个角，是遮挡最小的载体，44 亦为 iOS HIG 最小可点区域，不牺牲可点性；
- **入口位置**：右上角三竖点，与 §6.13 T6-② 「图层控制面板 = 地图右上角三个竖点展开」同一入口，不另开第二个筛选入口；
- **展开/收起动效**：底部上滑 240ms spring，遮罩渐显 180ms（§1.4.8）；
- **列表页不适用收起**：列表页无地图可让，筛选栏本就占布局流，保持常驻展开。

**地图底图口径（2026-08-24 补，回应「地图需要真实地图背景」）**：

- **底图供应商＝高德，不用 Google 地图**。三条硬理由：① Google Maps 未取得中国境内测绘资质，`maps.googleapis.com` 在境内被屏蔽，装机即白屏；② 国内 App 上架涉地图功能须提供《互联网地图服务资质》或第三方地图 API 授权证明，使用未授权境外地图数据是常见驳回原因；③ 与 §6.7 已定的高德原生 SDK 选型冲突，混用等于双份 SDK 体积 + 双份坐标系转换；
- **坐标系**：统一 GCJ-02（高德/国测局坐标）。若后续接入任何 WGS-84 数据源（如设备原始 GPS），须先转 GCJ-02 再落库，禁止两种坐标混存；
- **原型阶段的底图呈现方式**：底图以 Base64 内嵌在插件 `code.js` 末尾的 `MAP_BG_JPEG_B64` 常量里，生成时由 `mapBasePlate()` 解码后直接填充到名为 `_map-bg` 的矩形上，**9 个地图落点全自动带图，重跑插件无需任何手工操作**。此前一版留的是「手动贴图占位」，实测每次重跑要在 Figma 里重复贴 9 次，已于 2026-08-24 改为内嵌（回应「否则每次都要替换很麻烦」）。**不做运行时联网拉图**——插件 `manifest.json` 的 `networkAccess` 为 `none`，开白名单等于让原型生成依赖外部服务可用性，评审现场断网即失败；而 Figma 官方文档《Working with Images》明确 Base64 内嵌不产生网络请求，故白名单无需放开；
- **换底图流程**：替换 `docs/map-bg.png` → 在仓库根目录执行 `python tools/embed-map-bg.py`（自动裁切为 780×1376、JPEG q70、覆写常量段，幂等可重复执行）→ 回 Figma 重跑插件。底图在本地先裁成 390:688 而非交给 Figma 的 `scaleMode: FILL` 去裁，因为原图接近正方形，FILL 会自行丢弃约 41% 的横向像素，那部分字节等于白编码；
- **截图使用边界**：高德截图仅用于内部评审原型，须保留版权水印，不得去水印后对外发布或用于宣传物料。正式产品的底图由高德 SDK 在运行时渲染，不涉及截图。

**导航栏搜索框口径（2026-08-24 补，回应「地图界面差一个搜索框，输入关键字如"租房"快速过滤图层」）**：

上文 §6.3 与 §6.4.1 的 ASCII 图早已把搜索列为导航栏成员，但原型插件此前只实现了「地图/列表」视图切换，**Logo、搜索框、通知铃三件均漏实现**。本次补齐，并明确以下口径：

| 项 | 口径 | 判据 |
|---|---|---|
| 落点 | 导航栏（实体 48px），**不悬浮在地图上** | 地图左上 `x=16 y=12` 已被筛选摘要胶囊占据，右上是三竖点与图例入口；搜索框若也悬浮必与其中之一抢位 |
| 高度 | 32px（导航栏 48 上下各留 8 呼吸） | 输入框横向命中区宽 250px，实际可点面积远超 44×44 等效值，不适用图标按钮的 44px 下限 |
| 占位文案 | 「搜索保洁/拼车/租房」 | ASCII 图原句「就近的保洁/拼车/二手」20 字约需 240px，而搜索框内文案区实得约 204px，必被截断。压缩至 9 字约 108px |
| 未读通知 | 红点（8px），**不用数字气泡** | 导航栏仅剩 24px 见方，双位数气泡会溢出压到搜索框；精确条数由 `notification-screen` 承载 |
| 覆盖页面 | home-screen（全部 9 个画框）+ list-screen | 两页共享同一套筛选与范围状态（§10.1），搜索作为筛选的一环不应只有一页有；§6.4.3 列表页顶部规格亦含「搜索图标」 |

- **关键词过滤的语义**：关键词经**同义词映射**（§2.9）命中整个分类子树 —— 输入「租房」即命中 `房屋 › 租房` 下的整租/合租/单间三个三级类目，而非只做标题字面匹配。同义词表由运营后台配置（§2.10「分类同义词」）；
- **与既有筛选的关系**：关键词与「范围 / 供需 / 分类」三组筛选是**「与」关系**，互不覆盖。搜索不清空已选范围，已选范围也不忽略关键词；
- **收起态摘要必须同步回显关键词**：摘要胶囊若在有关键词时仍显示「全部分类」，就与导航栏搜索框自相矛盾，用户无从判断当前到底在筛什么。故有词时摘要改为「5km · 资源+需求 · 关键词「租房」」；
- **清空方式**：搜索框右侧叉号（仅有词时出现），点击后地图恢复全类目。无词时不渲染叉号——它无事可做，常驻只会占宽并误导可点；
- **不新增独立搜索页**：§2.6 曾提「搜索页：分类过滤区」，但 §10.1 页面清单 17 页内并无此页，属文档内部不一致。**本次定稿为「首页内搜索态」，§2.6 那句同步改为「首页搜索态」**，页面总数不变。理由是搜索的产出就是地图图层的过滤结果，独立成页反而要用户在两屏之间来回比对，与「地图优先」定位相悖；
- **原型呈现**：批次 2 新增 1 个变体画框「搜索过滤态 · 关键词「租房」」，刻意把默认 7 个 Pin 收成 3 个房屋类 Pin —— 过滤的效果必须体现在 Marker 的增减上，只改搜索框里的文字等于没过滤；
- **通知铃跳转**：`_nav-bell` → `notification-screen`。此前该页只有「我的 › 通知中心」一个入口，首页顶部的铃若不可点，用户看到红点却无处可去。

**图标实现形式（2026-08-24 定稿，取代此前 emoji 占位与手写路径两版）**：

图标资产**统一取 Material Symbols（filled 变体）官方路径**，许可 Apache 2.0，商用无限制。不得渲染 emoji 字符，也不再手写坐标。

- **图标映射表（以「大类的二级范围」为依据，不以 emoji 字面为依据）**：

| 大类 | 二级范围（§1 色板表） | Material Symbols 名 | 图形 |
|---|---|---|---|
| 工作 | 招聘 / 求职 | `work` | 手提箱 |
| 房屋 | 出租 / 求租 | `home` | 屋形 |
| 车辆 | 拼车 / 顺风车 / 租车 | `directions_car` | 车身 + 双轮 |
| 生活 | 二手 / 借物 / 互助 | `volunteer_activism` | 手托爱心（给出 + 善意） |
| 服务 | 家政 / 维修 / 教学 | `build` | 扳手 |

- **为什么废弃 emoji 占位（🌱🛎️ 是错的，不只是"不精细"）**：早先表格里生活写 🌱、服务写 🛎️。**叶片指向植物与环保，与「二手流转 / 借还 / 邻里互助」毫无关联；服务铃指向酒店前台呼叫，与「上门维修 / 家政 / 家教」不搭**。符号选错时画得再精细也认不出——**语义映射错误是「无法见图知意」的首要成因，优先级高于视觉精细度**；
- **为什么废弃手写 SVG 路径**：图标实际渲染仅 `40 × 0.5 = 20px`。手写坐标里 1.2px 的叶脉、1.4px 的箱体中缝在 20px 下不足 1 个逻辑像素，渲染即消失或糊成灰边。Material Symbols 每条路径均做过 20/24px 网格对齐，小尺寸下仍成形；
- **为什么选 Material Symbols 而非 Lucide / Heroicons**：Lucide（ISC）与 Heroicons（MIT）许可同样干净，但**主力是 outline 描边款**——2px 描边线图压在分类色实心圆底上对比度不足；Material Symbols 的 filled 变体是纯 `fill` 路径，与"资源态取白、需求态取分类色"的染色规则天然兼容，且 3000+ 图标同一设计网格，五类能在同库内配齐、不出现风格断裂；
- **小尺寸下「结构简单」优先于「语义精确」（重要取舍）**：服务类语义更全的是 `handyman`（锤子+扳手交叉），但 640 字符、两件工具在 20px 下会粘连，故改取单件 `build`；生活类同理排除 `recycling`（回收三角，实测 fill1 版 428 字符，4 组独立箭头间距不足 1px）、`handshake`（654 字符，双手交错）、`waving_hand`（567 字符，五指分开）三个候选；
- **生活类图标为什么是 `volunteer_activism`（2026-08-24 定稿，经 24 个候选真实尺寸渲染比对）**：此前先后用过 `swap_horiz`（左右双箭头）与 `package_2`（纸箱），均被否，判据如下：
  - **`swap_horiz` 被否于「语义关联太弱」**：箭头在界面里的通行含义是「操作/切换」，摆进 Pin 当品类标识会被读成控件而非事物；且它只表达「挪动」这个动作，而分类图标要表达的是被挪动的东西本身。更要紧的是**族群不一致**——工作=手提箱、房屋=屋形、车辆=汽车、服务=扳手四件皆为具象实物，唯独生活是抽象符号，五个并排时明显异质；
  - **`package_2` 被否于「覆盖不全」**：把 §2 分类树摊开后核出，生活下挂 5 个二级 / 15 个三级（二手闲置转让 5 / 借物互助 3 / 寻物失物 2 / 宠物相关 2 / 求购求助 2）。纸箱只覆盖物品侧 **11/15** ——**宠物是活物装不进箱子，邻里互助与求助是人情往来而非物品交易**，两支共 4 个三级类目落空；
  - **`volunteer_activism` 是唯一 15/15 全覆盖的图形**：一只手向上托起、心自手中升起，「给出」与「善意」两层动作恰好横跨「物品转让 + 帮助」双语义（二手=递出物品、借物互助=直接命中、失物招领=归还善意、宠物领养=善意托付、邻里求助=直接命中）。361 字符，手与心均为实心块面而非线条勾勒，20px 清晰、14px 仍能辨出轮廓；
  - **同时被否的双语义次选**：`loyalty`（标签带心，434 字符，语义组合最贴但 14px 下心与标签粘连）、`card_giftcard` / `redeem`（礼品卡·礼品袋，暗示预付与商业馈赠，与借物、求助两支不搭）、`sell`（价格标签，「标价」暗示必须付费，与借物/互助/求助三支冲突）、`weekend`（沙发，清晰但把品类窄化成家具）；
  - **方法论**：图标选型**不可凭 SVG 路径字符数推断可辨识度**。本轮先按字符数预判，多处结论被实机渲染推翻（`volunteer_activism` 曾被预判为「手掌笔画在 20px 偏细」，实测清晰；`support` / `communities` 曾按名称预判为扶助与社区语义，实测图形分别是方向盘与三瓣圆，与语义无关）。**须按真实尺寸（40px Pin / 20px 图层面板 / 14px 图例）渲染成对照图、肉眼比对后再定**。评审用的渲染脚本属一次性器材，判据既已沉淀于本节即不留存；日后若再选图标，按以下四步重建：① 从 `https://fonts.gstatic.com/s/i/short-term/release/materialsymbolsoutlined/<name>/fill1/24px.svg` 抓 `d` 属性，同时校验「单 path 且无 defs / 渐变 / 蒙版 / 额外图元」（`svgIcon()` 的硬限制，不合规须直接报错而非降级）；② 按 `pinRaw()` 的资源态（分类色填充 + 白图标）与需求态（白底 + 2px 分类色描边 + 分类色图标）两式各渲一份；③ 四档尺寸并排 —— 40px Pin / 40px 需求态 / 20px 图层面板 / 14px 图例；④ 与其余四类同排渲出，一并检验族群一致性；
- **技术适配**：Material Symbols 的 viewBox 为 `0 -960 960 960`（Y 轴负区间），非标准 `0 0 24 24`，导入时 viewBox 须随路径一起传入，否则 960 坐标系路径按小网格解析会整体跑出画布；
- **配色规则**：
  - 资源态＝分类色实心圆 + **白色图标**（圆底已是分类色，图标须取白才有对比）；
  - 需求态＝白底 + 分类色 2px 描边 + **分类色图标**；
  - 图标边长＝Marker 直径 × 0.5（40 时为 20，48 时为 24），四周留白保证小尺寸可辨；
- **需求态 "?" 位置**：从圆心移至**右上角 16×16 角标**（分类色实心 + 白描边）。原因是 §6.4.2 要求需求态同时具备「空心圆 + ?」与「分类图标」两条信息，若 ? 仍占圆心则与图标争位，40×40 内叠加不可读。改为图标居中承载「是什么类」、? 作角标承载「这是需求而非资源」，两条信息各有其位；
- **完整度角标（T6-③）不在地图 Marker 上常驻（2026-08-24 修订）**：改为**仅在点击 Marker 后的信息卡内**以「绿/黄/红色点 + 文字档位（信息完整 / 部分字段缺失 / 关键字段缺失）」呈现。原因是 40×40 内原先叠了 4 条信息（圆底色=分类、中心图标=分类、右上 ?=供需、右下小圆点=完整度），**分类被重复编码两次，而完整度在地图缩略态几乎无人细看，纯粹在抢辨识带宽**。卸掉后信息密度从 4 降到 3，图标可辨识度直接上一档。完整度本身不丢——它在信息卡与列表卡片内仍完整呈现；三档角标的形态规范仍保留在 T6-③ 规格板上，仅作规范演示，与地图实态刻意不一致；
- **验收口径（必须执行，否则等于凭感觉）**：T6 组件板须提供**「20px 真实尺寸对照条」（T6-⑤）**——五类 × 资源/需求共 10 个 Marker 以 100% 实际尺寸并排。**判据是屏幕缩放 100%、在手机臂展距离（约 40cm）能逐个说出是哪一类**；说不出即判不通过，须回到图标路径表换图形，而不是放大检视。此前两版图标被判"不够形象"，直接原因就是一直在 Figma 里放大到 400% 检视，从未在真实尺寸下验收。另须做**去色校验**：选中对照条加 Saturation −100（或黑白打印），若去色后仍能区分，说明形状本身承载了语义、没有全靠颜色硬撑（同时覆盖色弱用户场景）。

|---|---|---|
| ≥30 条（高密度） | 收窄至 **3km** 蜂窝精准近场 | "我身边就是密集" |
| 10-29 条（健康） | 保持 **5km** | 默认体验 |
| 3-9 条（轻度不足） | 扩至 **10km** + 浮层提示外有资源 | "外圈有资源，可看" |
| ≤2 条（空圈） | 自动扩到 **全城** + 触发 **30 秒分层响应兜底** | 不让用户空手离开 |

**30 秒分层响应兜底**（空圈触发）：
- **1 秒**：拉历史匹配（过去 7 天有匹配过的同分类发布）；
- **10 秒**：扩圈到全城同分类；
- **30 秒**：平台代发布 + 定向邀请（运营后台代发需求邀请资源方响应）。

**"平台代发布 + 定向邀请"的承载方式（本期落地口径）**：

| 项 | 规格 |
|---|---|
| 触发 | 空圈且 30 秒内三级兜底均无结果 → 该需求进「待运营跟进队列」（后台队列，用户端不可见） |
| 载体 | **不新建代发实体**：仍是用户本人那条需求，只加一个 `需运营协助` 内部标记；平台不以自己名义发布内容 |
| 定向邀请动作 | 运营在后台选中该需求 → 勾选同城同二级类目的活跃资源方（一次 ≤20 个）→ 触发站内通知 + 推送，文案"有人在找你提供的服务" |
| 邀请频控 | 同一资源方每日最多被定向邀请 2 次，计入 §6.14 每日 ≤10 条推送总额 |
| 用户端反馈 | 需求方在「我的发布」看到该条状态为"平台正在帮你找"；有资源方响应后转为普通推送通知 |
| SLA | 运营处理时限 24h；超时未处理则自动关闭协助标记并推送"暂时没找到，可以调整一下需求描述" |
| 本期范围 | 该能力**仅后台手动操作**，不做自动定向邀请（避免无监督群发形成骚扰） |

**兜底过程态（三级递进，全程不留空白页）**：

| 时点 | 界面表现 |
|---|---|
| 0–1 秒 | 鸭子 IP 缺省图 + "附近有点安静，正在帮你往外找…" + 骨架卡 3 条 |
| 1 秒返回 | 若历史匹配有结果，直接铺卡片并加"过去 7 天的同类信息"分组标题；无结果则保持上一态继续等 |
| 1–10 秒 | 文案切"正在扩大到全城范围…"，进度条走满 10 秒；用户可随时点"我自己调范围"退出等待 |
| 10 秒返回 | 全城同分类结果铺卡片，顶部提示"5 公里内暂时没有，这些在全城范围内" |
| 10–30 秒 | 文案切"已通知平台帮你找，稍后消息通知你"；**不强留用户**，显示「先去别处看看」按钮 |
| 30 秒仍无 | 落到终态空页：鸭子缺省图 + "已记下你的需求，有匹配会推送给你" + 「发一条需求，让别人来找你」主按钮 |

**定位权限降级（两段递进，第二段仅在第一段被拒后进入）**：

- **第一段 · 位置权限未开**：全屏引导页，突出"就近"价值 + 主按钮"开启位置权限"，次按钮"手动选择城市"；
- **第二段 · 用户仍拒绝或选择"手动选择城市"**：进入基站+商圈兜底态（非城市中心假值，避免误导），不阻塞发现。该兜底态同时是 §6.8「定位失败 ≥3 次」的降级终态。

- **地图加载失败**：降级为模拟地图（白底线框 + 道路模拟），不阻塞发现。

### 6.6 用户故事

- As a **本地居民**，I want **打开就看到身边 5km 内都有啥**，So that 我不用再搜全城。
- As a **找拼车的人**，I want **一眼在地图上看到 5 个橙色拼车 Marker**，So that 我马上选最近的那个。
- As a **没找到资源的人**，I want **空状态直接告诉我"发个需求让人找上门"**，So that 我不白白离开。
- As a **视力较弱的用户**，I want **资源和需求 Marker 一眼能分辨**，So that 我不把需求错当资源点击。

### 6.7 实现逻辑

- **客户端技术栈**：Flutter 跨端（**锁定 Flutter 3.41.9 / Dart 3.11.5**，不使用 3.44.x 及以上，避开其 SwiftPM 与 Android 混合合成底层改动带来的插件适配风险）；
- **地图 SDK**：高德地图 **Android / iOS 原生 SDK**，经 Flutter 插件 `amap_map` + `x_amap_base` 桥接（Android AMapSDK 10.1.200 / minSdk 21，iOS 10.1.200 / iOS 12.0+；Marker 样式按 §1 色板定制）；
  - **合规顺序**：先弹隐私协议获得同意，再调 `AMapInitializer.updatePrivacyAgree`，未同意不初始化地图；
  - **必配项**：`AndroidManifest.xml` 的 `<application>` 需声明 `android:allowNativeHeapPointerTagging="false"`，否则 targetSDK ≥30 时地图页返回会闪退；
- **范围条**：值为 1/3/5/10/全城（km）；调范围时：地图视野缩放、列表请求参数变化；
- **资源/需求开关**：两者都可开（默认全开）；仅开资源/仅开需求/全开三态；
- **Marker 聚合**：`amap_map` 插件不提供原生 MarkerCluster，聚合在 **Dart 侧自实现网格聚合**（按屏幕像素网格归并，阈值按 §6.15 分类差异化聚合阈值表），性能须经前置 POC 验证（详见 §6.10.1 D2 决策）；
- **轻量匹配**：**T1 LR+GBDT 两阶段**，详见 §6.12；
- **首页首屏**：定位完成前先显示骨架屏；定位失败显示降级 UI + 手动选城市；
- **数据分页**：地图 Marker 一次性取 ≤ 500 条；列表用无限滚动（每页 20）。

### 6.8 功能细节描述

| 边界 | 规则 |
|---|---|
| 定位失败 ≥ 3 次 | 降级为手动选城市 + 5km 不可用（基站+商圈兜底，非城市中心假值，详见 §6.4.4 S2） |
| Marker 过密（≥ 500） | 强制聚合；聚合最小时按 §6.15 分类差异化聚合阈值表聚（工作 3/房屋 5/生活 8）；缩放到最大级别不聚合 |
| 范围 = 全城 | 地图视野 = 用户定位所在城市行政边界；列表按城市过滤 |

| 排序切换 | 列表重排，加轻量骨架屏（每行渐变） |

### 6.9 T3 分类三级树图层弹层

**分类三级树图层弹层（T3）**：

- **入口**：地图右上角三竖点按钮（与 §6.13 T6-② 同一入口，不另设第二筛选入口）；
- **载体**：底部上滑弹层 + 40% 遮罩（§1.4.8：上滑 240ms spring / 遮罩渐显 180ms）。**为什么用弹层而不是把三层铺成悬浮条**：三级最深一层有 5-6 个类目，三层横条叠起来约 170px，会把 688px 地图吃掉四分之一还多；弹层是「按需占屏、用完即走」，不选时零占用；
- **第 1 层 · 5 大类顶栏切换**：工作/房屋/车辆/生活/服务（每个大类默认展开下一级），当前大类以分类色实心胶囊高亮 + 白色分类图标；
- **第 2 层 · 二级类目多选框**：例 房屋 → ☑️ 整租/合租 ☑️ 求租/找房 ☐ 短租/日租 ☐ 租房信息咨询（默认按最近 7 天发布数排序）；
- **第 3 层 · 三级类目精筛**：例 整租/合租 → ☑️ 主卧出租 ☐ 次卧出租 ☐ 整租出租（勾选任意级都立即加载）；
- **类目以 §2.4 为唯一定义源**（2026-08-23 修正）：本节示例原写「☐ 商铺」「☐ 隔断」，而 §2.4 房屋二级为「整租/合租、求租/找房、短租/日租、租房信息咨询」、三级为「主卧出租、次卧出租、整租出租」，并无「商铺」「隔断」二项。§2.4 是分类体系定义源（§2.3 已定层级与 ≤60 叶子上限），本节仅为交互层级举例，故示例文案已按 §2.4 校正；
- **复选框实现**：不得直接渲染 `☑️`／`☐` 字符（三端时而渲染为彩色 emoji、时而为黑白符号，尺寸与基线均不稳定），一律用 18×18 方框 + 矢量勾。选中态＝分类色填充 + 白勾，未选态＝白底 + `color/border` 1.5px 描边；
- **退出方式**（回应「选完可收起」）：底部动作行「重置 / 确定并收起」+ 标题行右侧「收起」+ 顶部把手下滑，三条退出口并存。确定后弹层整层退场，所选条件压缩为 §6.4.1 的收起态摘要胶囊。

**仅保留两种基础可视化**：供需实心/空心 + 🟢🟡🔴 完整度角标（**不做**信誉星级发光/撮合热力/四步决策导航器等偏离项）。

> **与 §6.13（T6 视觉交互）的边界**：本节的"两种基础可视化"约束的是**Pin 承载的信息维度**——Pin 只表达"供需态"与"完整度档"两类信息，不表达信誉、成交热度、决策阶段。§6.13 中的亮度差异（×1.3/×1.1/×1.0）与蜂窝密度着色属于**同一两类信息的强调手法**，不引入第三类信息维度：亮度只映射完整度档，蜂窝色深只映射**发布条数密度**（不含成交/撮合数据）。因此二者不冲突。

### 6.10 三层性能保障 SLA = P95≤300ms

**三层性能保障规格（T3）**：

| 层级 | 名称 | 规格 |
|---|---|---|
| 🟦 第 1 层 | 预渲染 | 打开 APP 瞬间后台一次性预渲染 5 大类的聚合 Marker（1000 条以内不超过 50ms） |
| 🟦 第 2 层 | 按需取数 | 勾二级/三级时才按"分类ID+半径+坐标"从后端拉取对应 Pin（每次请求 ≤10KB） |
| 🟦 第 3 层 | 本地三级缓存 | 大类 1 小时 / 二级 15 分钟 / 三级 5 分钟，命中分类组合直接读本地不发请求 |

**P95≤300ms 的口径边界（避免被理解成只测渲染）**：

- **计时起点** = 用户手指离开分类 Tab / 类目勾选框的那一刻；**计时终点** = 该分类的 Pin 在地图上完成首屏绘制；
- **因此这段耗时包含四段**：本地缓存查找 → 网络请求（未命中时）→ Dart 侧聚合计算 → Pin 渲染上屏，**四段之和 ≤300ms**，不是只算最后一段；
- **网络分段单列子指标**：未命中缓存时接口 RT P95 ≤150ms（否则整体必然超标），该子指标与整体一同埋点上报；
- **弱网口径**：4G 及以上网络下统计 P95；2G/3G 与断网会话不计入分母，改为走 §6.4.4 的过程态与降级 UI。

**本地三级缓存键（完整键定义，缺一即视为未命中）**：

| 组成 | 说明 |
|---|---|
| 分类 ID | 命中到最细一级（一/二/三级各自成键） |
| 供需态 | 仅资源 / 仅需求 / 全开，三态不可混用缓存 |
| 半径档 | 1/3/5/10/全城，**档位不同即不同键**（不做半径向下兼容复用） |
| 坐标网格 | 用户定位按约 500m 网格取整后的网格 ID（避免移动几十米就全量失效，也避免跨街区错读） |
| 数据版本号 | 分类树版本号（运营改配置即全量失效，对齐 §3.7 的版本号比对机制） |

- **失效规则**：任一组成变化 → 未命中，重新请求；到达 TTL（大类 1h / 二级 15min / 三级 5min）→ 过期；
- **缓存容量**：单设备最多保留 50 个键，超出按最近最少使用淘汰。

#### 6.10.1 D2 决策兜底：Batch1 前置聚合性能 POC + 性能日志埋点 + 降级开关应急

> **决策 D2**：客户端为 Flutter + 高德原生 SDK 桥接（§6.7），聚合由 Dart 侧自实现，**没有可直接引用的官方聚合性能规格**。因此 Batch1 排期内前置 1 天聚合性能 POC，**POC 通过后才把 P95≤300ms SLA 写入 BRD/PRD 承诺**。

**理由**：P95≤300ms 是 §0.2 北极星三轴之一（分类图层加载成功率）的判定基准，不能建立在无外部规格支撑的假设上；1 天 POC 成本远低于上线后返工。

**POC 验收口径**：

| 项 | 规格 |
|---|---|
| 机型 | 低端安卓（2GB RAM）+ 中端安卓 + iPhone 各 1 台 |
| 数据量 | 单屏 1 万点、5 万点两档 |
| 通过线 | 图层切换 P95 ≤300ms 且帧渲染稳定 ≤16ms |
| 不通过时 | 单次渲染上限下调至 500 Pin 并把 SLA 改写为实测值，同步修订 §0.2 北极星第二轴基准 |

**识别风险**：Dart 侧聚合在低端安卓机上可能出现 FPS<10；若不前置验证，风险后置到上线时才暴露。

**兜底方案**：

1. **性能日志埋点（Batch1 开发同步实施，零额外成本）**：图层切换耗时 + FPS + 内存峰值三项指标实时上报，P95>300ms 自动告警；
2. **预留"性能降级开关"应急方案（不立即实施，仅文档化）**：
   - **触发条件** = 连续 3 次帧渲染 >16ms 或 P95 >800ms；
   - **降级动作** = 关闭聚合动画 / 单次渲染上限 500 Pin（超出按距离衰减裁剪）/ 弹 toast"当前区域信息较多，已开启性能模式"；
3. **假设 A8 验证方式**：POC 结论为准；上线后第一周复测实网 P95，若不达标则启用降级开关。

### 6.12 T1 LR+GBDT 两阶段匹配

**T1 LR+GBDT 两阶段**：

| 步骤 | 名称 | 规格 |
|---|---|---|
| **Step 1** | 标签强度打标 | 联系点击×5 / 详情页点击×2 / 详情停留 30s×1（仅取联系点击/位置/时效/类目，**不取撮合反馈、不设成交核销环节**，Scope 对齐） |
| **Step 2** | 一阶 LR 召回 | 五因子 + 非线性距离惩罚 + 分层池 |
| **Step 3** | 二阶 GBDT 精排 | 100 棵树 + 40 特征（行为 × 上下文） |
| **Step 4** | Top 30 展示 + 10% Explore | 🔴/🟡 新发布打破茧房（10% 流量探索新发布） |

**Hard Filter 前置**：必须同三级类目 + 同城 + 同需求态（资源对需求 / 需求对资源）。

**供需分模型**：
- **资源方模型权重**：时效 60% / 距离 30% / 认证 10%；
- **需求方模型权重**：认证 40% / 完整度档 40% / 时效 20%（完整度档 = 🟢1.0 / 🟡0.5 / 🔴0.2，**不使用信誉分**）。

**10% 用户双轨灰度**（仅在冷启动阶段 2 样本量达标后开启）：GBDT 组 vs PRD 基线加权组，连续 7 天**推送触达后的详情点击率**（只统计点击动作，不追踪撮合结果）≥+15% → 100%，否则立刻回滚基线。

**冷启动降级（模型无数据可训时的唯一口径）**：

| 阶段 | 触发条件 | 生效算法 |
|---|---|---|
| **阶段 0 · 规则期** | 全站累计有效行为标签 <1 万条 或 上线 <4 周 | **只跑规则加权**：时效 40% + 距离 40% + 完整度档 20%，Hard Filter 不变；GBDT 不启用，看板该轴按 §0.2.1 冷启动观察期处理 |
| **阶段 1 · LR 期** | 标签 ≥1 万条 | 启用一阶 LR 召回，精排仍用规则加权 |
| **阶段 2 · 全量期** | 标签 ≥10 万条 且 单类目样本 ≥2000 条 | 启用二阶 GBDT 精排，进入 10% 双轨灰度 |

- **单用户冷启动**：新用户无行为标签时，用「同城 + 同二级类目 + 最近 7 天」热门排序兜底，不返回空列表；
- **单类目冷启动**：某三级类目样本不足 2000 条时，该类目回落到其二级类目模型；二级仍不足则回落规则加权；
- **降级不可逆判定由后台开关控制**，运营可强制回落到阶段 0（应对模型异常）。

### 6.13 T6 三轴联动飞轮视觉交互规格

**三轴联动视觉交互规格（T6）**：

- As a **发布者**，I want **我的手机号先脱敏、想看才显示**，So that 我不被爬虫和骚扰电话采集。
- As a **看到需求的人**，I want **详情页有个"我能帮忙"的捷径**，So that 我顺手就发布一个对应资源。

### 7.7 实现逻辑

- **详情页字段渲染**：根据 `post.leaf_category_id` → 取对应模板 Schema → 渲染模板字段区（按序显示 key/value）；
- **媒体轮播**：支持图片 + 视频；图片点击可全屏查看；视频点击内置播放器；
- **详情地图**：高德小地图 + Marker，点击"查看大图"进全屏地图选点（复用地图选择器只读模式）；
- **联系事件（北极星指标统计点）**：用户每次点击"查看完整号码并外呼"或"复制微信号"后，后端写入 contact_event（post_id, from_user_id, to_user_id, channel_type=phone/wechat, timestamp），作为"首次联系触发率"唯一统计点（**只记录联系动作是否发生，不追踪后续是否成交**）；
- **脱敏**：手机号 `138****8888`，微信号默认隐藏中段；
- **反爬/反采集（S7 单轨）**：
  - 完整号码不写入前端初始状态，通过点击时走 API 拉取（带频率限制）；
  - **统一防爬限频（三维同时生效，任一超限即拒绝）**：同一账号每日 ≤30 次、同一设备指纹每日 ≤30 次、同一 IP 每日 ≤100 次（**额度不按实名状态分层**）；
  - **仅登录用户可拉取完整号码**，未登录一律拦截，使代理池换 IP 无法绕过账号维度上限；
  - **异常访问熔断**：单账号 1 分钟内 ≥10 次拉取 → 当日冻结该能力 + 进运营风控待审列表；
  - 前端图片渲染号码而非文本（可选增强）；
- **举报**：点举报 → 选原因（不实信息/诈骗/违规类目/骚扰/其他）→ 提交 → 进入 §9.10.3 风险分累计与后台复核。

| 边界 | 规则 |
|---|---|
| 未登录点联系 | 弹登录 → 登录成功回中转页 |
| 对方联系方式未填 | 主按钮禁用 Toast 提示："对方未留联系方式，尝试举报让其补充" |
| 联系次数超限 | 提示"今日联系数已达上限，明天再来"（S7 单轨：额度不分层，按账号/设备/IP 三维判定） |
| 点外呼失败（模拟器/Pad 无拨号能力） | 自动降级为"复制手机号到剪贴板" |
| 详情页分享 | 生成短链：标题 + 封面图 + 分类色 + 距离；落地在 H5 页面（未装 APP 提示下载） |

### 9.5 用户故事

- As a **用户**，I want **我的默认范围（3km）永久记住**，So that 每次打开不用滑条再调。
- As a **用户**，I want **看到违规内容能一键举报**，So that 平台干净。
- As a **用户**，I want **注销账号时给我冷静期**，So that 我不冲动删档。

### 9.6 实现逻辑（合规与治理）

- **敏感词过滤**：发布时标题/描述走本地词库（前端快速拦截）+ 云端词库（提交时校验）；命中后不允许发布，提示"包含敏感词：xxx，请修改"；
- **图片审核**：媒体上传 → 云端内容审核（涉黄/涉政/广告）；未通过的图片显示"该图未通过审核，无法发布"；
- **违规类目**：禁发清单（医疗/药品/金融理财/武器/色情/违法服务等），运营可配；命中时强制拦截并弹"此类信息平台禁止发布"；
- **举报与下架**：统一走 §9.10.3 举报分级响应引擎（唯一判定口径：累计风险分 ≥60 自动下架 + 人工复核），本节不另设举报次数或举报率阈值；
- **申诉通道**：下架后用户可在通知中点"申诉"，填写原因+凭证+提交，24h 内回复；
- **数据最小化**：
  - 位置只存发布时选择的经纬度点，不存轨迹；
  - 联系方式存储加密，APP 端只在联系时显式拉取；
  - 身份证号只存不可逆哈希 + 后 4 位明文，不存完整明文；姓名加密保存；OCR 原照加密后 7 天删除（与 §4.7 同一口径）；
  - **媒体元数据剥离**：图片上传后服务端强制清除 EXIF（含 GPS、设备、拍摄时间），仅保留发布时用户主动选择的经纬度点。

### 9.7 功能细节描述

| 边界 | 规则 |
|---|---|
| 敏感词可绕过 | 同音字、变体需配同义词；云审 + 本地双重 |

#### 9.10.3 举报分级响应引擎（全站唯一下架判定口径）

**本节是"被举报后是否下架"的唯一判定规则，§3.7 / §7.8 / §9.6 均引用本节，不另设阈值。**

- **举报方门槛**：仅已实名用户可提交举报；同一举报人对同一条发布仅计 1 次（重复提交不累加）；被运营打标为误报的举报不计入累计；
- **原因分 5 类各配基础风险分**：诈骗收费 = 50 / 不实信息 = 20 / 违规类目 = 20 / 骚扰 = 10 / 其他 = 5；
- **举报方权重**：普通实名用户 ×1，企业认证用户 ×1.5；
- **触发条件**：单条发布累计风险分 ≥60 → 自动下架 + 人工复核；
- **响应动作**：自动下架 + 紧急工单 SLA ≤4h + 举报人 24h 闭环反馈；
- **申诉**：下架后走 §9.6 申诉通道，申诉成立则恢复上架并清零该条累计风险分。

### 12.5 统一错误码

**分段规则**：前 3 位对齐 HTTP 状态码语义（`400` 参数 / `401` 鉴权 / `403` 权限 / `409` 内容冲突 / `410` 已失效 / `429` 限流 / `500` 内部 / `503` 依赖不可用），后 2 位为该段内序号。**`4xxxx` 客户端可修正，`5xxxx` 服务端或第三方故障。**

| code | HTTP | 含义 | 客户端处置 | 来源 |
|---|---|---|---|---|
| `0` | 200 | 成功 | — | — |
| `40001` | 400 | 参数缺失或非法（含 `/map/pins` 缓存键要素不全） | 修参重试，不提示用户 | §6.10 |
| `40002` | 400 | 协议未勾选 | 主按钮保持 Disabled | §3.8 |
| `40101` | 401 | 未登录 / Token 失效 | 弹登录，登录成功回原页 | §7.8 |
| `40105` | 401 | 登录失败 5 次，锁定 15 分钟 | 显示剩余锁定时间 | §3.8 |
| `40301` | 403 | 未实名详情额度耗尽（每日 3 条） | 弹半屏引导「去实名（约 30 秒）」+「明天再来」，返回原列表 | §3.7 |
| `40302` | 403 | 高敏类目未认证，禁止发布 | 弹 `cert-modal` 跳认证 | §5.7 |
| `40303` | 403 | 该类目禁发（医疗/金融/武器等） | 弹「此类信息平台禁止发布」 | §9.6 |
| `40304` | 403 | 未实名发布已达上限（每日 1 条 / 在库 3 条） | 引导实名 | §3.7 |
| `40901` | 409 | 命中敏感词 | 提示「包含敏感词：xxx，请修改」 | §9.6 |
| `40902` | 409 | 图片未通过内容审核 | 该图位显示「该图未通过审核，无法发布」 | §9.6 |
| `41001` | 410 | 信息已下架/过期 | 页面 Opacity 60% + 顶部红条，联系按钮禁用，收藏保留 | §7.8 |
| `42901` | 429 | AI 配额耗尽 | 提示剩余额度与重置时间，降级手动填写 | §5.8 |
| `42902` | 429 | 联系方式拉取超限（账号/设备/IP 任一） | 提示「今日联系数已达上限，明天再来」 | §7.8 |

| `42904` | 429 | 推送频控（≤10 条/日） | 服务端静默转站内通知，客户端无感 | §6.14 |
| `50001` | 500 | 服务端内部错误 | 通用重试 + 回显 `request_id` | §12.1 |
| `50301` | 503 | AI 解析不可用（超时 / 无返回 / 图不可识别） | 停留原页，Error toast + 「重试」「改为手动填写」，已输入内容全保留 | §5.9 |
| `50302` | 503 | 第三方认证服务不可用 | 支持手动重填字段 + 转人工复核 | §4.8 |
| `50303` | 503 | 地图/定位服务不可用 | 定位失败 ≥3 次降级手动选城市 | §6.8 |

**错误提示口径**：`4xxxx` 用具体文案（用户能改），`5xxxx` 用统一「服务暂时不可用，请稍后重试」+ `request_id`，**禁止把服务端堆栈或第三方原始报错透传到 UI**。

## 14. 非功能需求（NFR）

### 14.1 性能

| 指标 | 目标 | 判定口径 | 来源 |
|---|---|---|---|
| 分类图层切换 | **P95 ≤300ms** | 四段之和（缓存查找 + 网络 + Dart 聚合 + Pin 渲染），4G 及以上网络统计 | §6.10 |
| 读接口 RT | **P95 ≤150ms** | 未命中缓存时的服务端响应，单列上报 | §6.10 |
| 预渲染 | 5 大类聚合 Marker **1000 条内 ≤50ms** | 冷启动后台一次性完成 | §6.10 第 1 层 |
| 帧渲染 | **≤16ms**（60fps） | POC 三机型实测 | §6.10.1 |
| 地图取数体积 | 单次 **≤10KB** | 按需取数每请求 | §6.10 第 2 层 |
| 单次渲染上限 | 500 Pin | 超出强制聚合 | §6.7 / §6.8 |
| 双向推送时延 | 发布后 **1min 内**触达 Top20/Top30 | 需求推 Top20 资源方 / 资源推 Top30 需求方 | §6.14 |

- **P95≤300ms 须经 §6.10.1 的 Batch1 前置 1 天 POC 验证后才成为对外承诺**；POC 不通过则渲染上限下调至 500 Pin 并按实测值改写 SLA，同步修订 §0.2 北极星第二轴基准；
- **降级开关**（预留不实施）：连续 3 次帧渲染 >16ms 或 P95 >800ms → 关聚合动画 + 上限降 500 Pin + toast「当前区域信息较多，已开启性能模式」（§6.10.1）。
