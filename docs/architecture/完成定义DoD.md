# 完成定义（Definition of Done）

> 版本：v1.0（2026-09-09）
> 适用范围：Batch1 编码期全部条目（说明文档 §2.8 Sprint Backlog，条目 [121]–[131]）。
> 定位：**条目验收的唯一执行清单**。本文只做检查项编排与证据要求，验收口径本身一律引用《编码规范》（`docs/architecture/编码规范.md`）章节号，**不复制其条文**；两者冲突时以《编码规范》及其依据源为准，先回写本文再验收。

---

## 0. 使用方式

- 每个条目收尾时，逐节核对：§1 通用项全过 + §2 中该条目类型的附加项全过 + Backlog 表中该条目「特有验收点」全过，三者齐备才算 Done。
- 每项核对必须留**可复核证据**（命令 + 关键输出/计数），写入进度记录对应条目；无证据视同未做。
- 「扫描面为空是 SKIP 不是 PASS」：任何扫描类检查若目标集合为空（如无新增文件可扫），结论记 SKIP 并注明，严禁记通过。
- 任一项不过 → 条目不关闭、不合分支，当场修复或按 §4 登记豁免。

## 3. 证据与记录格式

进度记录条目收尾段固定写三行：

```text
- 验收证据：<命令> → <关键输出/计数>（逐 DoD 项可追加）
- 门禁结论：PASS / SKIP（扫描面为空）/ FAIL（附处置）
- 遗留与豁免：无 / 见豁免登记 <编号>
```

## 4. 豁免纪律

- 豁免只能针对 D 项检查，**不能豁免 FAIL 本身**（部署 §14.5：FAIL 不可豁免）。
- 豁免须显式登记：编号、理由、影响面、**删除条件与到期时间**，写在进度记录条目内；到期未关闭视同阻塞。
- SKIP 与豁免均需在 Sprint 检查点复核一次。

## 5. 变更纪律

- 本文变更必须同步检查：说明文档 §2.8 Backlog「特有验收点」列、《编码规范》被引章节是否存在漂移；三者保持一致方可提交。
- 新增条目类型（如后台管理）先补 §2 对应附加节，再允许该类型条目启动。
