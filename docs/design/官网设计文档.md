## 1. 目标、范围与验收

### 1.1 为什么做

微信开放平台「创建移动应用」将**应用官网**设为必填且须可访问（不支持公众号 / 小程序 / H5 顶替）。现有 `s2s.build110.com` 只反代 API，根路径无页面，因此阻塞 B2-6a 资质提交。官网同时承担：

1. 应用商店与开放平台审核时的**产品说明载体**；
2. 《用户协议》《隐私政策》的**自有域名独立 URL** 托管（商店硬要求，第三方文档平台不被接受）；
3. **ICP 备案号**与运营主体的公示位（APP 备案要求）。

### 1.2 本期范围

| 做 | 不做 |
| --- | --- |
| 首页：价值主张 + 应用简介 + **应用下载** + 4 个服务功能详情 + 3 步上手 + 信任与边界 | 分发统计 / 渠道归因 / 灰度分发后台 |
| **下载区**：APK 直链 + 版本/大小/SHA-256 + 安装说明 + 应用市场占位（上架后补链接） | 假下载按钮 / 隐藏下载 / 诱导跳转 |
| **`/flow` 应用运行流程图**：同一版本真机截图串起主流程 + 可下载流程图 PNG | 小程序截图 / 他人 App 截图 / 与申请信息不一致的旧图 |
| `/terms` 用户协议、`/privacy` 隐私政策两个独立 URL | 博客 / 新闻 / 帮助中心 / 多语言 |
| 页脚：版权所有者、ICP 备案号（链接工信部）、联系方式、免责声明 | 在线客服 / 留言表单 / 账号体系 |
| 响应式：390px 手机优先，兼容桌面与微信内置浏览器 | 后台 CMS（文案变更走仓库提交） |
| SEO 基础：title / description / OG / robots.txt | 数据埋点、Cookie、任何第三方脚本 |

### 1.4 硬约束（不可在开发中自行放宽）

1. **备案号不得套用旧域名**：`皖ICP备18025259号-3` 属 `build110.com`，新域名须用其自身备案号；未取得前页面显示占位并在验收时替换。
2. **简介逐字一致**：官网页与开放平台「移动应用简介」为同一文案，任一处修改必须同步另一处（列入发布检查单）。
3. **下载必须真实可用（驳回①）**：下载按钮必须指向可访问的 APK（HTTP 200，支持 Range），且页面展示的版本号、文件大小、SHA-256 与文件实际值一致；**禁止**假按钮、空链接、隐藏入口或仅写「即将上线」。
4. **流程图必须同源同版（驳回②）**：`/flow` 截图与提交微信的流程图必须来自**同一提审包**、同一套图；不得混用旧版本渲染图、小程序截图或他人 App 截图；官网流程图文件与开放平台上传文件须为同一文件（验收比对 SHA-256）。
5. **三处身份一致**：应用名称「找丫找」、包名 `com.s2s.zhaoyazhao.dev`、签名 MD5 `30FBC1A8A7A4D57E9CB87BFD9B22D076`、版本号 V1.0.x 在 **App / 官网 / 开放平台** 三处一致；全站与截图禁用「顺手邻里」等旧名、占位名。
6. **不出现交易承诺**：全站不写「担保」「成交」「支付」「最快」「第一」等表述；统一声明「仅提供信息发布、展示与联系通道，不参与交易、不提供担保」。
7. **零外部依赖**：不引第三方字体、CDN、统计脚本、客服插件；所有资源同域。
8. **协议正文以法务审阅稿为准**：预览页只演示版式；上线前由 `docs/legal/` 正式稿转换，禁止用预览中的节选直接上线。

### 1.5 微信驳回整改对照（v1.1）

| 驳回意见 | v1.0 设计 | 差距判定 | v1.1 整改 |
| --- | --- | --- | --- |
| ① 官网须包含**应用下载**、介绍等基础内容（或应用市场下载链接），以便用户识别应用真伪 | 有应用介绍；**明确不做下载入口**（担心未上架） | 🔴 **不匹配（硬缺口）** | 首页新增 `#download` 下载区：APK 直链 + 版本/大小/SHA-256 + 安装说明 + 应用市场占位；新增应用信息核验卡（名称/包名/签名 MD5/开发者） |
| ② 提交流程图与应用名称/信息不一致，涉嫌使用他人 App 流程图 | 无流程图页；仅在 B2-6a 任务书写了「须真实截图」 | 🟠 **部分匹配（缺交付物与一致性机制）** | 新增 `/flow` 页：同一提审包真机截图 6 步 + 应用身份卡 + 可下载流程图 PNG；建立「同一文件、同一哈希」验收规则 |
| 备注：如涉及授权委托须附授权书 | — | ⚪ 不适用 | 本应用为自有应用（主体 = 合肥嘉联），**无需授权书**；若未来使用第三方素材，另行补充 |

## 2. 信息架构与路由

### 2.1 站点地图

```
/                首页（唯一营销页：介绍 + 下载 + 流程入口）
├── /flow        应用运行流程图（与应用市场/开放平台提交同源）
├── /download/*  APK 与流程图文件（Caddy 静态，不入 git）
├── /terms       用户协议（独立 URL，未登录可访问）
├── /privacy     隐私政策（独立 URL，未登录可访问）
├── /assets/*    CSS / Logo / 截图
├── /robots.txt
└── /favicon.ico
```

- 不设 `/about`、`/contact`：主体与联系方式放页脚，减少页面数量与维护面。
- 协议页与流程图页顶部提供「返回首页」，页脚保留同样的合规信息，确保从任何入口进入都能看到备案号。

### 2.2 导航模型

| 位置 | 内容 |
| --- | --- |
| 顶部导航（吸顶） | 产品功能（`#features`）、**运行流程（`flow.html`）**、**下载（`#download`）**、用户协议、隐私政策 |
| 首屏主按钮 | **「下载 Android 版」→ `#download`**；次按钮「了解功能」→ `#features` |
| 下载区 | APK 直链、SHA-256、安装说明、应用市场占位（上架后补） |
| 页脚 | 协议与政策、联系我们、应用信息（版本/包名）、备案信息、免责声明 |

移动端（≤560px）导航隐藏前三个页内入口，仅保留「用户协议 / 隐私政策」；下载入口由首屏主按钮与 `#download` 区块承载，保证手机端仍可见。

### 2.3 页面骨架（首页）

```
[Header 吸顶 64px]
[Hero]        左：eyebrow / H1 / 说明 / 双按钮（下载 / 了解功能）
              右：两台手机截图（首页地图 + AI 确认页）+ 同心波纹背景
[Intro]       应用简介（与开放平台逐字一致）
[Download]    下载区：APK 版本/大小/更新日期 + 下载按钮 + 二维码位
              应用信息核验：名称/包名/签名 MD5/SHA-256/开发者
[Features]    四卡：AI 智能发布 / 地图分类图层 / 双向供需 / 完整与可信
[How]         三步：拍图或说一句 → AI 生成草稿并确认 → 地图上就近相遇
[Trust]       深青面板：真实、克制、可核对（三条）
[Footer]      品牌 / 协议 / 联系方式 / 应用信息 + 备案 + 免责声明
```

### 7.2 Caddy 路由（验收点 ⑤ 的关键）

**原则：只把明确的静态路径交给 `file_server`，其余一律保持原反代。** 不使用 SPA fallback，避免吞掉 API 404 语义。

```caddyfile
{$SITE_DOMAIN} {
    tls { protocols tls1.2 tls1.3 }
    encode gzip

    # —— 官网静态白名单（新增） ——
    handle /flow {
        rewrite * /flow.html
        file_server { root /srv/www }
    }
    handle /terms {
        rewrite * /terms.html
        file_server { root /srv/www }
    }
    handle /privacy {
        rewrite * /privacy.html
        file_server { root /srv/www }
    }
    handle /download/* {
        header Cache-Control "public, max-age=86400"
        @apk path *.apk
        header @apk Content-Type "application/vnd.android.package-archive"
        file_server { root /srv/www }
    }
    handle /assets/* {
        header Cache-Control "public, max-age=604800"
        file_server { root /srv/www }
    }
    handle /robots.txt  { file_server { root /srv/www } }
    handle /favicon.ico { file_server { root /srv/www } }
    handle /            { file_server { root /srv/www } }

    # —— 其余全部回落 API，行为与现状一致 ——
    handle {
        reverse_proxy app:8080 {
            header_up X-Real-IP {remote_host}
            header_up X-Forwarded-For {remote_host}
            header_up X-Forwarded-Proto {scheme}
            health_uri /actuator/health
            health_interval 30s
            health_timeout 5s
        }
    }

    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options "nosniff"
        X-Frame-Options "DENY"
        Content-Security-Policy "default-src 'self'; img-src 'self' data:; style-src 'self'; script-src 'none'; frame-ancestors 'none'; base-uri 'self'; form-action 'none'"
        -Server
    }

    log { ...保持现状... }
}
```

> 实现时须在 staging 先验证 `handle` 匹配顺序：路径匹配器按具体度排序、裸 `handle` 兜底。验证方法见 §8 T4。

### 7.6 缓存与安全头

- HTML：`Cache-Control: no-cache`（允许协商缓存，避免文案更新滞后）。
- `/assets/*`：`public, max-age=604800`；文件名带内容哈希或版本号（`site-v1.css`）。
- `/download/*`：`public, max-age=86400`；APK 的 Content-Type 固定为 `application/vnd.android.package-archive`，流程图 PNG 按文件扩展名。
- `robots.txt` 允许首页/协议/流程图，`Disallow: /download/` 避免搜索引擎抓取大文件。
- CSP 禁止任何脚本（`script-src 'none'`），从机制上排除第三方注入；后续若需统计，须单独评审。

## 9. 风险与待确认

| 风险 | 影响 | 处置 |
| --- | --- | --- |
| 新域名 ICP 未下 | 无法作为「应用官网」提交 | 设计与开发先行；域名下来后只替换占位并验收 |
| 备案号填错（套用旧域名） | 审核驳回 / 违规 | 页脚占位保留到备案下证；发布检查单强制核对 |
| 协议未经法务审阅 | 不得上线 | 设计阶段只用节选；T3 以正式稿为准 |
| 简介两处不一致 | 开放平台驳回 | 三处同步规则写入 §5.1 与发布检查单 |
| Caddy 路由误伤 API | 线上故障 | 显式白名单 + T4 回归清单 + staging 先行 |
| **APK 被仿冒或篡改** | 用户安装假包 / 审核质疑 | 页面公开包名 + 签名 MD5 + SHA-256；官方唯一下载渠道声明；签名与提审包一致 |
| **APK 直链 125MB 下载失败/过慢** | 审核方无法安装验证 | 支持 Range；页面标注大小；提供 SHA-256 供断点续传后校验；必要时后续拆分 arm64 包 |
| **应用市场尚未上架** | 下载区出现空链接 | 未上架只显示「待上架」文本，不放假链接；APK 直链始终可用 |
| **流程图二次不一致** | 再次驳回 | 同一提审包截图；官网与开放平台使用同一 PNG；发布检查单比对 SHA-256 |
| 截图与线上功能不一致 | 审核质疑 | 截图取自最终提审包真机；功能变更时同步重截并重新合成流程图 |
