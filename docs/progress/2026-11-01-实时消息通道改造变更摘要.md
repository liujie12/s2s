# 实时消息通道改造 · 变更摘要

> 日期：2026-11-01
> 范围：站内 1:1 会话消息的实时投递（前台）与桌面角标提醒（后台）
> 结论：代码已按「多实例安全」实现，部署仍为单实例；后端 / 前端 / Android 全量门禁通过

---

## 1. 要解决的问题

| # | 现象 | 根因 |
| --- | --- | --- |
| 1 | 消息延迟大，不能准实时 | 前端没有轮询、没有长连接、也没有「回前台刷新」；只有进页面/下拉/发消息时才拉取，App 在前台反而完全收不到新消息 |
| 2 | 桌面图标不提醒 | ① 角标只由 Dart 层在未读数变化时下发，App 不在前台时该值永不更新；② 原生 `MiPushReceiver` 未处理「通知到达」回调；③ 通知权限只在「发布成功」时申请，从未发帖的用户永远不被询问；④ 小米推送凭据仍未配置 |

## 2. 方案

**WebSocket + Redis Pub/Sub fan-out，连接层无状态。**

- 每个实例只维护本机连接表；
- 消息落库后（事务提交后）写 Redis 频道，全实例订阅，各自只投本机连接；
- 因此**不需要粘性会话**，扩容＝加实例；单机故障只影响本机连接，客户端重连后靠 HTTP 补齐；
- 实时通道只是加速器：HTTP 的 `after_seq` 增量与 `unread-summary` 才是最终真源。

```
发送方 App ──HTTP──> 实例 A ──落库──> MySQL
                        └─(提交后)─> Redis 频道 ──fan-out──> 实例 A / 实例 B ──WS──> 接收方 App
```

## 4. 关键行为与边界

| 场景 | 行为 |
| --- | --- |
| 消息发送成功 | 提交后广播；客户端收到后按 `seq` 增量拉取，**不直接下发正文** |
| 事务回滚 | 不广播（`AFTER_COMMIT`），不会出现「幽灵消息」 |
| App 进后台 | 主动断开长连接，提醒交给厂商推送；后台收到通知点亮红点 |
| App 回前台 | 重连 + 重拉未读与会话列表首页，当前会话由页面增量补齐 |
| 同账号第 4 端登录 | 踢掉最早连接（关闭码 4002），旧端**不自动重连**，避免两端互踢 |
| 实例连接数满 | 拒绝新连接（关闭码 4001），客户端退避后重连可能落到其它实例 |
| 慢客户端 | 发送超时 5s / 缓冲 512KB，超限断开该连接，不拖累投递线程 |
| Redis 不可用 | 消息照常落库；跨实例投递失效，客户端靠 HTTP 补齐；不报错、不回滚 |
| WebSocket 不可用 | 客户端退避重连，期间退回「下拉/回前台刷新」，功能不中断 |

## 5. 容量与扩容

| 项 | 当前 | 说明 |
| --- | --- | --- |
| 单实例连接上限 | 3000 | JVM `-Xmx600m` 下的保守值，**需压测校准**（估算安全线约 5k） |
| 每连接内存 | 15–25KB（估算） | 含 Tomcat socket 缓冲与会话对象 |
| 文件描述符 | **必须调到 ≥65535** | 容器默认 1024，不改会卡在千级连接 |
| 扩容触发线 | 连接数 > 上限 70% / 投递 P99 > 200ms / CPU > 70% | — |
| 扩容动作 | 加实例 + Caddy 写多上游 | compose scale 后 Docker DNS 只回一个 IP，Caddyfile 必须显式列地址 |
| 总线放大 | N × 消息速率 × ~150B | 1k msg/s × 5 实例 ≈ 0.75MB/s，Redis 压力可忽略 |

## 7. 上线前置条件

1. **小米推送凭据**（阻断项，与本次代码无关）：
   - 客户端：`android/local.properties` 的 `mipush.appId` / `mipush.appKey`；
   - 服务端：`XIAOMI_PUSH_ENABLED=true`、`XIAOMI_PUSH_APP_SECRET`、`XIAOMI_PUSH_PACKAGE_NAME`。
   - 未配置时：实时通道（前台）可用，**后台提醒仍然不会响**。
2. **宿主文件描述符**：容器 `nofile` 需 ≥65535，否则连接数到千级即失败。
3. **Caddy**：v2 默认透传 WebSocket 升级，单实例无需改配置。

## 8. 已知限制（本期不做）

- 只有**文本消息**触发实时事件；联系方式申请卡、审批结果等卡片消息仍靠进页面拉取；
- iOS 未接 APNs，`AppBadge` 在 iOS 直接短路；
- 未做「输入中 / 在线状态」（PRD 明确不做）；
- 后台角标只表示「有未读」（红点），精确数字待后续透传方案；
- 未实现登出/封禁时服务端主动断开该用户连接（当前靠客户端登出断开 + 连接空闲断开）；
- 客户端使用 `dart:io` WebSocket，**不支持 Flutter Web**（本项目为移动端，暂不需要）。

## 9. 回滚方式

- 服务端回滚到上一镜像即可：无数据库迁移、无 schema 变更，旧客户端不受影响（`/ws` 是新增端点，旧版不会访问）；
- 客户端回滚到上一安装包：服务端保留 `/ws` 不产生副作用（无人连接）；
- 紧急止血：把 `RealtimeLimits` 的频道订阅停用或直接回滚镜像，HTTP 拉取链路仍然完整可用。
