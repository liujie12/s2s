📐 第一部分：需求还原的 5 条主题轴（Axes）

5 条轴来源于 Grounding 的显性矛盾与缺口，每条轴在 6 个 Frame 中至少被 2 条想法覆盖。

A1 双向撮合落地完整性　BRD 喊"双向撮合"是魂，但 PRD 匹配算法仅单向打分排序、需求态只有被动地图发现无主动推送——双向 UI 有了，双向匹配机制半残。候选想法：S1 / S2。
A2 北极星指标与真实价值断层　"点联系=撮合成功"是假繁荣：100次点击0成交，平台完全不自知。跳转后黑盒是最大数据盲区。候选：S1 / S3 / S6。
A3 5km半径与供给密度矛盾　冷启动5km=空圈、密度上来5km=冗余；位置权限拒=以城市中心为基准5km假值=近场价值直接消失。候选：S2 / S4 / S7。
A4 信任层级与降级路径缺失　仅实名/资质两档，初期70%用户无锚；无申诉机制；无动态衰减=僵尸资质依旧挂首页推荐。候选：S3 / S6。
A5 运营治理后台黑洞　PRD 写"分类/模板/权重可配、举报SLA24h"，实际后台一页都没定义。运营想加类目得等研发排期2周，战机全失。候选：S4 / S5 / S7。

A5 运营后台黑洞A4 合规治理高置信

一句话主张：把 PRD 中所有"后台可配"的口头承诺落实为 4 个后台 MVP 页面（分类配置+模板配置+权重配置+举报工单），交付排期与前端 P0 同步（而非扔给"未来再做"）；叠加 72h 临时类目快速验证通道 + 举报风险分+工单SLA闭环+举报人反馈，让运营不再是 PRD 的旁观者。

4 个后台 MVP（必须与前端 P0 同排期）：
① 分类配置 CRUD（名称/父类/模板/颜色/图标/资质标记）→ JSON 推 CDN + 版本号 3 秒生效
② 模板 Schema 编辑器（可视化字段拖拽）
③ 撮合权重配置 + AB 开关（距离/时效/分类/关键词/认证）
④ 举报工单列表（按风险分排序、自动下架、批量处理）
72h 临时类目：运营发现新需求→挂在「生活→临时→XXX」下→72h 自动下线→如果 3 天内该类目发布数 ≥ 3 且被联系数 ≥ 5 → 自动进入"转正候选池"走正式分类评审。窗口期不浪费。

指标杠杆：新增三级类目生效从 2 周 → ≤10 分钟；举报自动下架准确率从 0% → ≥80%；举报人满意度从 0% → ≥60%；运营"想干活但没工具"的流失率归 0
PRD 修改点：新增「运营治理后台」独立章节（10-15 页），明确 4 个 MVP 页面字段/权限/SLA；PRD §2.9 分类配置从接口契约升级为页面规格
落地难度：中（纯 CRUD 后台，技术风险低；但需要产品把规格写全，不能继续用"后台可配"一句话带过）
Evidence：58 同城 2024 年新增内容安全团队 500 人+下架 1.2 亿条，举报分类工单是合规基础；小红书分类三级改二级 → 发布转化率 +62% 背后也是后台配置快。
