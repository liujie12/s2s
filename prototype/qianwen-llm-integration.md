# 千问大模型集成方案

## 1. 集成架构

### 1.1 系统架构
```
前端 → 大模型服务接口 → 千问大模型API → 响应处理 → 搜索逻辑
```

### 1.2 集成方式
- **前端直接调用**：使用浏览器的fetch API直接调用千问大模型API
- **CORS处理**：需要确保千问大模型API支持CORS，或通过代理服务器转发

## 2. 千问大模型API集成

### 2.1 API配置
- **API Endpoint**: `https://ark.cn-beijing.volces.com/api/v3/chat/completions`
- **API Key**: 需要从千问大模型平台获取
- **请求方法**: POST
- **请求头**: 
  - `Content-Type: application/json`
  - `Authorization: Bearer {API_KEY}`

### 2.2 请求格式
```json
{
  "model": "ep-20260202123456-abcde", // 集群千问大模型部署ID
  "messages": [
    {
      "role": "system",
      "content": "你是一个智能搜索助手，负责理解用户的搜索意图并提取关键信息。"
    },
    {
      "role": "user",
      "content": "请分析以下搜索查询，提取关键词、识别实体、预测分类：{user_query}"
    }
  ],
  "temperature": 0.3,
  "max_tokens": 500
}
```

### 2.3 提示词设计
```
你是一个智能搜索助手，负责理解用户的搜索意图并提取关键信息。

请分析以下搜索查询，按照要求输出结果：

搜索查询：{user_query}

输出要求：
1. 提取核心关键词（去除停用词）
2. 识别实体（如工具、服务、物品等）
3. 预测最可能的资源分类（person/car/skill/item）
4. 识别用户意图（搜索资源还是发布需求）
5. 分析情绪倾向（positive/neutral/negative）
6. 给出置信度（0-1之间的数字）

请以JSON格式输出，字段名如下：
- keywords: 关键词数组
- entities: 实体数组，每个实体包含type和value字段
- category: 预测的分类
- intent: 用户意图（search/demand）
- sentiment: 情绪倾向
- confidence: 置信度
```

## 3. 响应处理

### 3.1 千问大模型响应格式
```json
{
  "id": "chatcmpl-123",
  "object": "chat.completion",
  "created": 1677858242,
  "model": "ep-20260202123456-abcde",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "{json_response}"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 120,
    "completion_tokens": 150,
    "total_tokens": 270
  }
}
```

### 3.2 响应解析
1. 提取 `choices[0].message.content` 中的JSON字符串
2. 解析JSON字符串为JavaScript对象
3. 转换为与当前模拟实现兼容的格式

## 4. 错误处理与重试机制

### 4.1 错误类型
- **网络错误**: 网络连接失败
- **API错误**: API返回错误码
- **超时错误**: 请求超时
- **解析错误**: 响应格式不符合预期

### 4.2 重试策略
- **最大重试次数**: 3次
- **重试间隔**: 指数退避（1s, 2s, 4s）
- **重试条件**: 网络错误、服务端错误（5xx）

### 4.3 降级策略
- 当大模型调用失败时，使用传统的关键词提取和分类逻辑
- 确保搜索功能在大模型不可用时仍然可以正常工作

## 5. 性能优化

### 5.1 缓存策略
- **本地缓存**: 使用localStorage缓存近期的搜索结果
- **缓存过期时间**: 30分钟
- **缓存键**: 用户查询的哈希值

### 5.2 请求优化
- **防抖处理**: 已实现300ms防抖
- **批量处理**: 合并短时间内的多次搜索请求
- **预加载**: 预测用户可能的搜索意图，提前进行大模型调用

### 5.3 提示词优化
- **精简提示词**: 减少提示词长度，提高响应速度
- **结构化输出**: 明确要求JSON格式输出，减少解析错误
- **示例引导**: 在提示词中包含示例，提高千问大模型的输出质量

## 6. 安全考虑

### 6.1 API密钥保护
- **前端存储**: 避免在前端代码中硬编码API密钥
- **环境变量**: 使用环境变量存储API密钥
- **后端代理**: 考虑通过后端服务器转发请求，隐藏API密钥

### 6.2 输入验证
- **输入长度限制**: 限制用户输入长度，避免恶意长输入
- **输入内容过滤**: 过滤恶意或敏感内容
- **速率限制**: 限制单个用户的请求频率

### 6.3 输出安全
- **内容审核**: 对千问大模型的输出进行内容审核
- **格式验证**: 验证输出格式，确保符合预期
- **错误处理**: 对异常输出进行合理处理
